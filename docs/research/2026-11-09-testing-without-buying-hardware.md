# Free Runners Reach Real CPUs, Not Machines

**Yes, the project can test on real x86-64 processors today for free, and it has already done so. But these are real processors, not real machines.** On 9 November 2026 a free GitHub Actions runner booted the Origin kernel under QEMU with KVM on a real AMD EPYC 7763, and all 8 boots reached the kernel's last line. The same run found a problem that QEMU's software CPU had hidden: drawing one console line took 4.3 to 4.6 ms with interrupts off. The IOMMU, NVMe, PCIe, firmware and ACPI tables in that run were still QEMU's, so it says nothing about real devices or real firmware. Those start at about ₹10 to ₹40 an hour on a rented whole server, but the owner must sign up first and will often face an ID check. No free or rented option is documented to boot Origin on a platform launched in 2026 or later. Only a PC or laptop that someone already owns can show laptop firmware, sleep and USB behaviour. The best order is this: free KVM in CI, then free tools for CET and bad devices, then a few paid hours on one rented server, then volunteers with a safe USB image. **Nothing in this report qualifies a release.** `CLAUDE.md` §74, §76 and rules 30 and 40 require physical tests on the declared machines.

*How to read this report.* **Run** means the project ran it. **Page** means a researcher read the provider's own page on 9 November 2026. **Snippet** means only search-result text or a third-party page was seen. **Reasoning** means no source says it. Nobody signed up with any provider, and no rented or cloud machine was booted. "KVM" here always means Linux's virtual machine feature. A remote screen and keyboard is called a "remote console". The IOMMU is the part that stops devices from reaching memory they should not. CET shadow stacks are a hardware check on return addresses. Speculation controls are CPU switches against Spectre-style attacks. Hybrid cores are fast and slow cores in one CPU. TCG is QEMU's software CPU. Rupee figures use the 6 November ECB rate, $1 = ₹93.92 and €1 = ₹104.86 ([Frankfurter](https://api.frankfurter.dev/v1/latest?base=USD&symbols=INR,EUR)). Prices exclude tax.

## Eight free boots already put the kernel on a real CPU

**This is the strongest evidence here, because the project ran it.** On 9 November 2026 the kernel booted on a free GitHub Actions `ubuntu-24.04` runner in the project's public repository ([run 42547942738](https://github.com/vighnesha-os/origin-os/actions/runs/42547942738), branch `trial/real-x86`). The runner had 4 vCPUs on an AMD EPYC 7763. It showed `svm`, nested virtualization was on, and `/dev/kvm` worked after one udev rule. It needed no account or payment beyond the existing GitHub repository. QEMU 11.1.3 used KVM, so the real CPU executed the kernel's instructions. The whole job took 14 minutes, and 4.5 of those went to building QEMU.

| Boot | Reached the last line | One console line, average and worst (ms) | Bus-master quiesce (s) | PCID and INVPCID |
|---|---|---|---|---|
| TCG control, Intel VT-d model, 2 CPUs | Yes | 0.57 and 1.66 | 0.09 | No |
| KVM, VT-d model, 1 CPU | Yes | 4.35 and 6.77 | 0.77 | Yes |
| KVM, VT-d model, 2 CPUs | Yes | 4.32 and 7.12 | 0.89 | Yes |
| KVM, VT-d model, 4 CPUs | Yes | 4.45 and 9.99 | 0.80 | Yes |
| KVM, AMD-Vi model, 2 CPUs | Yes | 4.29 and 6.53 | 0.90 | Yes |
| KVM, AMD-Vi model, 4 CPUs | Yes | 4.39 and 9.07 | 0.89 | Yes |
| KVM, sparse x2APIC (APIC IDs above 255) | Yes | 4.33 and 6.88 | 0.77 | Yes |
| KVM, `-cpu host`, 4 CPUs | Yes | 4.56 and 7.60 | 0.90 | Yes |

**SMEP, SMAP, UMIP, SYSCALL, swapgs, ring-3 processes, x2APIC, XSAVE, SMP start-up, preemption, TLB shootdowns, and NVMe and virtio I/O all ran with the real CPU executing the kernel's instructions.** In plain words, the CPU's kernel protections, system calls, user programs, multi-CPU start-up and task switching all ran on real cores. PCID and INVPCID appear under KVM and not under TCG. Two cautions keep this honest. First, the CPU was real, but the hardware around it was not. The timer, the interrupt controller, the IOMMU, NVMe and PCIe were software models in KVM and QEMU. The runner's own CPU flag list has no `x2apic`, so the x2APIC the kernel used was software. Second, a green tick proves less than it looks. In KVM mode the test harness only checks that the boot reached the end, and it ignores the proof described next (`developer-tools/xtask/src/main.rs` on the trial branch). The results for each proof come from reading the logs.

**One proof could not pass under KVM.** The kernel made an I/O APIC pin's interrupt-remap entry not present, and then gave it a wrong source ID. Neither step stopped the pin's interrupts. This happened in all five KVM boots that use the Intel VT-d model. The AMD-Vi boots do not run this proof yet. With a split irqchip, QEMU keeps the old KVM route, and its error output shows that it did refuse the entry. This is a limit of QEMU with KVM, not of the kernel.

**KVM exposed costs that TCG had hidden.** Drawing one console line on the uncached framebuffer took 4.3 to 4.6 ms on average and up to 10 ms at worst, with interrupts off. TCG took about 0.57 ms on the same runner and about 0.23 ms on the Mac. Stopping devices from using memory at boot (the bus-master quiesce) took 0.77 to 0.90 s against 0.09 s under TCG, because configuration-space reads trap under nested virtualization. All 32 of 32 timer-calibration windows were judged disturbed, and the result was still right. These numbers come from a VM inside a VM. They prove that the costs exist. They do not say what a real PC will measure.

**A newer free run answers part of the CET question.** [Run 42550240456](https://github.com/vighnesha-os/origin-os/actions/runs/42550240456), started later on 9 November, used an `ubuntu-26.04` runner with Linux 7.0.0-1019-azure on an AMD EPYC 9V74. QEMU with KVM reported `cet-ss` true and `cet-ibt` false, and it started with `-cpu host,+cet-ss,enforce`. So this free runner can offer CET shadow stacks to a guest. That is not yet proof that they work, because QEMU was paused at start with `-S` and no guest instruction ran. KVM CET needs Linux 6.18 or later and QEMU 11.0 or later ([KVM pull](https://lkml.iu.edu/hypermail/linux/kernel/2509.3/07039.html), [QEMU 11.0](https://www.qemu.org/2026/04/22/qemu-11-0-0/)). Both runner images meet that: the image used for the eight boots lists kernel 7.0.0-1017-azure ([manifest](https://github.com/actions/runner-images/blob/ubuntu24/20261101.360/images/ubuntu/Ubuntu2404-Readme.md)).

**The limits are plain.** The EPYC 7763 is a 2021 server part, outside the project's 2026-or-later target. GitHub promises nothing. Its 2024 changelog announced hardware acceleration on Linux runners ([GitHub changelog](https://github.blog/changelog/2024-04-02-github-actions-hardware-accelerated-android-virtualization-now-available/)), but a runner-images maintainer wrote in August 2026 that nested virtualization "isn't officially supported" ([issue 14062](https://github.com/actions/runner-images/issues/14062)). A July 2026 image rollout hurt KVM-based Android tests and was rolled back ([issue 14482](https://github.com/actions/runner-images/issues/14482)). A job cannot choose its CPU. One project's 63 builds saw 70% EPYC 7763 and about 10% Intel Xeon ([duscope PR 121](https://github.com/kawadeomkar/duscope/pull/121)). The research found no report of KVM working on those Intel runners. One project also found no performance counters on a runner ([Laplace issue 236](https://github.com/Ikey168/Laplace/issues/236)). Standard runners are free for public repositories, and a job can last 6 hours ([billing](https://docs.github.com/en/billing/concepts/product-billing/github-actions), [limits](https://docs.github.com/en/actions/reference/limits)).

**Read the table by question, and the path becomes clear.** Real CPU behaviour is free today. One rented server is the first place that shows a real IOMMU, real NVMe and PCIe, and real firmware and ACPI tables. CET has three steps: Bochs for the logic, the free runner for real cores behind a hypervisor, and a rented machine for the bare chip. CET first shipped on Intel's Tiger Lake (Snippet, [Intel](https://intel.com/content/www/us/en/newsroom/opinion/intel-cet-answers-call-protect-common-malware-threats.html)), and AMD's Zen 3 has shadow stacks ([The Register](https://www.theregister.com/2021/03/15/zen_3_amd_epyc/)). Both runners showed `user_shstk`. Older CPUs do not have it, including the Xeon E3, E-2288G and E5 parts and the Ryzen PRO 3600 in the table below (Reasoning). Speculation controls need bare metal. On run 42547942738 the runner's flag list showed none of `ibrs`, `ibpb`, `stibp` or `ssbd`, so the hypervisor does not offer them there. No emulator can show that a mitigation actually works. Hybrid cores start at €0.0945 an hour on the Hetzner EX44. Sleep and resume need a client PC, and §67 requires physical tests for laptop power management. USB, USB4, Thunderbolt and docks need a machine and dock that someone owns.

## Free tools test logic, but only code that exists

**The first gap is in the kernel, not in the tools.** A search of `framekernel` and `boot` at commit `ed78f9d`, made for this report, finds no CET code and no speculation-control code. §14 requires CET shadow stacks. So no tool can test these features until the code exists.

**Bochs 3.1 is the best free CET test bench.** It was released on 23 August 2026 and boots OVMF ([Bochs news](https://sourceforge.net/p/bochs/news/), [changes](https://raw.githubusercontent.com/bochs-emu/Bochs/master/bochs/CHANGES)). It implements CET in software for both user and kernel mode ([cet.cc](https://github.com/bochs-emu/Bochs/blob/master/bochs/cpu/cet.cc), [exception.cc](https://github.com/bochs-emu/Bochs/blob/master/bochs/cpu/exception.cc)). Homebrew ships it for Apple Silicon with CET off, so it needs a custom build ([formula](https://github.com/Homebrew/homebrew-core/blob/HEAD/Formula/b/bochs.rb)). Nobody has tried that build on an M1. Bochs has no NVMe, AHCI or IOMMU ([device list](https://github.com/bochs-emu/Bochs/tree/master/bochs/iodev)), so it checks CPU logic only. Its CET code was still getting fixes in late 2026, so a failure there needs a second look. A small test image that prints the same results under TCG, Bochs and KVM will show where they disagree (Reasoning).

**No ready-made hostile PCI device exists, so the project must write one.** The research found no standard tool that attacks a custom kernel through a bad device. On the Mac the most direct route is a custom QEMU device, starting from the `edu` teaching device (Reasoning; [edu docs](https://github.com/qemu/qemu/blob/master/docs/specs/edu.rst)). QEMU also has built-in error injection through `blkdebug` and NVMe's `smart_critical_warning` ([blkdebug](https://github.com/qemu/qemu/blob/master/docs/devel/testing/blkdebug.rst), [NVMe code](https://github.com/qemu/qemu/blob/master/hw/nvme/ctrl.c)). The `vfio-user-pci` device needs Linux, so that route belongs in CI ([Kconfig](https://github.com/qemu/qemu/blob/master/hw/vfio-user/Kconfig)). OpenVMM has a programmable faulty NVMe controller, but it needs an x64 host ([fault.rs](https://github.com/microsoft/openvmm/blob/main/vm/devices/storage/nvme_resources/src/fault.rs)). §4 allows these as tracked test tools. §3 says their code must never become kernel code.

**Other simulators add little.** VirtualBox 7.2 is a real second set of device models, with NVMe, xHCI, HPET and both IOMMU types under GPLv3 ([changelog](https://www.virtualbox.org/wiki/Changelog-7.2), [source](https://github.com/VirtualBox/virtualbox)). It needs an x86-64 host, and one public VirtualBox job on GitHub failed on every scheduled run from 28 September to 2 November 2026 ([run list](https://github.com/Univers42/hellish/actions/workflows/born2root-vm.yml)). Intel's Simics public release needs an x86-64 host. Its licence requires a copy to Intel 30 days before publishing research based on it ([licence](https://www.intel.com/content/dam/develop/external/us/en/documents/isim-tools-license-agreement.pdf)). That fits badly with a public repository, so the owner should read it first. gem5 26.0 has no x86 UEFI path and no AVX decode, so `x86-64-v3` code will not run ([release notes](https://github.com/gem5/gem5/blob/stable/RELEASE-NOTES.md), [decoder](https://github.com/gem5/gem5/tree/stable/src/arch/x86/isa/decoder)). AMD SimNow's public page returned 404 on 9 November ([AMD](https://www.amd.com/en/developer/simnow-simulator.html)). VMware Workstation is free but needs a Broadcom account ([Broadcom](https://knowledge.broadcom.com/external/article/368667/download-and-license-vmware-desktop-hype.html)).

**A free cloud trial adds a second firmware, not real hardware.** Google Cloud is the best fit. It gives $300 for 90 days and needs a card, with a hold of $0 to $1 ([free features](https://docs.cloud.google.com/free/docs/free-cloud-features)). It documents a custom-OS path and 16550A serial ports ([custom OS](https://docs.cloud.google.com/compute/docs/images/building-custom-os)). A custom image can also carry its own Secure Boot keys ([Shielded images](https://docs.cloud.google.com/compute/shielded-vm/docs/creating-shielded-images)). So it can test the loader on UEFI and ACPI that QEMU did not write. Third-generation and later VMs use NVMe, which Origin already drives. Older E2 VMs use virtio-SCSI, and Origin has no driver for that. AWS offers $100 to $200 in credits and a serial console from the first boot message ([plans](https://docs.aws.amazon.com/awsaccountbilling/latest/aboutv2/free-tier-plans.html), [serial console](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/ec2-serial-console.html)). Its Free plan needs no card for most new customers ([FAQ](https://aws.amazon.com/free/free-tier-faqs/)), but it probably refuses a self-registered image (Reasoning; [image attribute](https://docs.aws.amazon.com/AWSEC2/latest/APIReference/API_Image.html)). Oracle's Always Free micro VMs take only listed images ([reference](https://docs.oracle.com/en-us/iaas/Content/FreeTier/resourceref.htm)). Azure needs VMBus drivers before a kernel can see a disk ([VMBus](https://docs.kernel.org/virt/hyperv/vmbus.html)), so it comes last. None of these proves anything about physical devices.

**Free credits do not reach bare metal.** Google's trial cannot raise quotas, and its smallest listed x86 metal has 192 vCPUs ([quotas](https://docs.cloud.google.com/compute/quotas), [metal](https://docs.cloud.google.com/compute/docs/instances/bare-metal-instances)). Oracle bars custom images on metal ([Bring Your Own Image](https://docs.oracle.com/en-us/iaas/Content/Compute/References/bringyourownimage.htm)). AWS's Free plan excludes `.metal` types ([eligible types](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/ec2-free-tier-usage.html)). AWS still takes applications for open-source credits by email. Origin's MIT or Apache-2.0 licence meets the licence rule, but the programme favours projects that matter to AWS ([AWS](https://aws.amazon.com/blogs/opensource/aws-cloud-credits-for-open-source-projects-affirming-our-commitment/)). phoenixNAP says it gives open-source projects free infrastructure, with a contact form and no stated criteria ([phoenixNAP](https://phoenixnap.com/company/open-source-community)). A request becomes stronger once public boot evidence exists (Reasoning).

**Start with Latitude.sh, then use Hetzner.** Latitude is the only hourly provider whose documentation says the serial console shows the firmware and early kernel output. The serial path matters because of a decision the owner has already made. ADR-0007 says identity maps for firmware-reserved memory must land before real hardware (`docs/adr/ADR-0007-iommu.md`, questions 4 and 8). Threat T14 explains why: without them, an integrated GPU can go dark when the IOMMU starts (`docs/engineering/THREAT_MODEL_IOMMU.md`). Hetzner's EX44 is the cheapest real hybrid CPU found, but its console is video only, and that video most likely comes from the CPU's built-in graphics (Reasoning). So it should come after identity maps exist. The console's price is also unclear. An October 2025 page says the console is free for three hours, and an October 2026 price list says €10 each time ([console](https://docs.hetzner.com/robot/dedicated-server/maintenance/kvm-console/), [price list](https://docs.hetzner.com/robot/general/pricing/price-list-for-additional-products/)). Budget €10 until support confirms otherwise.

**Spend the first hour on the provider's rescue Linux, not on Origin.** Copy the ACPI tables. Check that the machine is in UEFI mode. Check for DMAR or IVRS, the tables that describe the IOMMU, and for SPCR, the table that names the serial port. This needs no Origin code and risks nothing. ADR-0009 H6 also lists what the owner must close or accept before the first real-hardware boot (`docs/adr/ADR-0009-hardware-targets.md`). Delete the server the same day, because billing runs until you do. Hetzner caps the EX44 at €59 a month and says billing is hourly ([cancellation](https://docs.hetzner.com/general/billing-and-account-management/cancellation/cancellations-robot)).

**Several traps are documented, and more are unknown.** UEFI cannot be assumed. Vultr's iPXE route does not support EFI images on bare metal ([iPXE](https://docs.vultr.com/ipxe-boot-feature)). On Hetzner, community guides say UEFI needs a support request or a BIOS change ([tutorial](https://community.hetzner.com/tutorials/freebsd-openzfs-via-linux-rescue/)). The Latitude pages read do not mention UEFI. Latitude also warns that some server models lack the browser console. No provider page read says whether VT-d or AMD-Vi is on by default, whether tenants can enrol Secure Boot keys, or what the serial port's address is. The kernel already reads SPCR and draws on the framebuffer, but this is proven only under QEMU. Real disks prove less than the QEMU boots do. On any disk that is not the boot test's own, the kernel writes nothing and skips its storage proofs (`framekernel/src/storage.rs`). So a rented boot shows the real controller starting, not real disk I/O, until someone adds an opt-in mode for a disposable disk. The kernel starts at most 64 CPUs and leaves the rest in firmware (`framekernel/src/smp.rs`). For Indian cards, new cross-border rules began on 1 October 2026 ([Cashfree](https://www.cashfree.com/blog/reserve-bank-of-india-rbi-mandate-reshapes-cross-border-card-payments-into-india/)), so a one-off prepayment is safest (Reasoning). Community reports on Hetzner accepting Indian customers are mixed ([forum](https://lowendtalk.com/discussion/comment/3126623/)).

**No rental reaches the declared target.** None of the catalogues read lists a platform launched in 2026 or later. The newest rentable parts are EPYC 4005, Xeon 6, EPYC 9005, Ryzen 9000 and Core Ultra 200S, all from 2024 or 2025 ([Vultr](https://api.vultr.com/v2/plans-metal), [OVH](https://eu.api.ovh.com/1.0/order/catalog/public/baremetalServers?ovhSubsidiary=IE), [Hetzner](https://www.hetzner.com/dedicated-rootserver/matrix-ex/), [Google metal](https://docs.cloud.google.com/compute/docs/instances/bare-metal-instances), [Oracle shapes](https://docs.oracle.com/iaas/Content/Compute/References/computeshapes.htm)). ADR-0009 declares Panther Lake and Gorgon Point machines as the first targets. Under ADR-0009 H2, any older rented machine is bench equipment only. Monthly and deposit offers do not suit a short test. OVH charges a setup fee equal to a month and does not guarantee a management console on cheap lines ([catalogue](https://eu.api.ovh.com/1.0/order/catalog/public/eco?ovhSubsidiary=IE), [OVH forum](https://community.ovhcloud.com/t/probleme-ipmi-kvm/53105)). Hivelocity takes a first month as a deposit for hourly use ([billing](https://developers.hivelocity.net/docs/billing)).

**Large-cloud metal starts at about ₹255 an hour and has no clean boot path.** Oracle's cheapest current shape is BM.Optimized3.36 at $2.712 an hour by my arithmetic from its price list, with a one-hour minimum ([prices](https://apexapps.oracle.com/pls/apex/cetools/api/v1/products/?currencyCode=USD), [billing](https://docs.oracle.com/iaas/releasenotes/changes/20facdce-34bf-4648-a0a7-de5db73657ce/index.htm)). Oracle bars custom images on metal but documents custom iPXE scripts ([CLI](https://docs.oracle.com/en-us/iaas/tools/oci-cli/latest/oci_cli_docs/cmdref/compute/instance/launch.html)). It also lets tenants set the IOMMU, SMT and NUMA layout at launch, which makes it the best IOMMU test bench on paper ([BIOS settings](https://docs.oracle.com/iaas/Content/Compute/References/bios-settings.htm)). AWS c5n.metal is $3.888 an hour ([price feed](https://b0.p.awsstatic.com/pricing/2.0/meteredUnitMaps/ec2/USD/current/ec2-ondemand-without-sec-sel/US%20East%20%28N.%20Virginia%29/Linux/index.json)). Its documents list bare metal as an exception to UEFI support, and a boot can take 20 minutes or more ([UEFI](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/launch-instance-boot-mode.html), [Nitro](https://docs.aws.amazon.com/ec2/latest/instancetypes/ec2-nitro-instances.html)). A legacy BIOS path would not satisfy §19. IBM is the only large cloud that documents custom UEFI images for metal, but it requires a Pensando network driver, and its price could not be verified ([IBM](https://cloud.ibm.com/docs/vpc?topic=vpc-bare-metal-image)). Use these only if cheaper machines leave a specific question open.

## Only other people's machines reach laptops, sleep and 2026 firmware

**The research found no public lab that lets an outsider boot their own OS on a 2026 client PC.** KernelCI labs run kernels built by KernelCI ([KernelCI](https://docs.kernelci.org/intro/platform-testing/)). AMD's programmes list data-centre GPUs and EPYC, not Ryzen AI laptops ([AMD](https://www.amd.com/en/developer/resources/cloud-access.html)).

**Intel Cloud Services is the one official remote route to Panther Lake, and it gives data, not a boot.** Intel added India on 4 September 2026 ([release notes](https://cloud.intel.com/docs/release_notes.html)). Its public console code names a request-only bare-metal type, `bm-ptl`, for Core Ultra Series 3 processors ([console code](https://cloud.intel.com/assets/index-DL8eaOfS.js)). That does not prove it is in stock. Sign-up asks for a company email address, each request is reviewed, and a reservation cannot exceed 30 days ([sign-in](https://cloud.intel.com/docs/how_to_register.html), [request](https://cloud.intel.com/docs/how_to_request.html)). The OS comes from Intel's list ([access](https://cloud.intel.com/docs/how_to_access.html)), and the console code never mentions UEFI, BIOS, Secure Boot or custom images. Use it to record CPUID, ACPI tables and core layout for ADR-0009's Panther Lake target. Do not start Origin from Intel's Linux without Intel's written permission, because nobody could read the agreement's terms.

**A person who already owns a 2026 laptop is the only route to real 2026 client firmware, sleep and USB.** About 141 Core Ultra Series 3 laptops were listed for India on 31 October (Snippet, [Smartprix](https://www.smartprix.com/laptops/intel_core_ultra_series_3-cpu_gen)). Other projects show how this works. Redox keeps a table of working and broken machines, with its image date on each row ([HARDWARE.md](https://gitlab.redox-os.org/redox-os/redox/-/raw/master/HARDWARE.md)). FreeBSD started a laptop testing project in April 2026, with anonymised reports sent as pull requests ([FreeBSD](https://freebsdfoundation.org/blog/call-for-testing-introducing-the-laptop-integration-testing-project/)). SerenityOS removed its hand-kept list in 2025 as rarely updated ([history](https://github.com/SerenityOS/serenity/commits/master/Documentation/HardwareCompatibility.md)), so the report should be a file that a tool turns into a table row (Reasoning). The value is real: one Lenovo laptop exposed five Asterinas bugs, including a wrong CPU count and a black screen after DMA setup ([issue 1963](https://github.com/asterinas/asterinas/issues/1963)).

**Safety comes before reach, because a volunteer's data is P0.** Today's kernel is not ready for this. It writes nothing to disks that are not its own test disk, which is good, but it still starts NVMe and network devices. A volunteer image needs its own build with those drivers left out. It should boot only from the removable-media path, chosen once by the volunteer, and never write UEFI variables, because such writes bricked Samsung laptops in 2013 (Snippet, [The Register](https://www.theregister.com/2013/03/22/uefi_boot_memory_full/)). It should write only to its own stick, carry no storage or network drivers, run briefly, and tell the volunteer how to stop it. Sleep should be a separate opt-in choice. Turning Secure Boot off can trigger BitLocker recovery, so the volunteer must hold the recovery key first ([Microsoft](https://learn.microsoft.com/en-us/troubleshoot/windows-client/windows-security/bitlocker-recovery-known-issues)). The report stays on the stick until the volunteer decides to send it, with serial numbers and MAC addresses removed (§61). College or employer machines need written permission from the person in charge (Snippet, [IT Act s.43](https://cis-india.org/internet-governance/resources/section-43-it-act.txt)). Without identity maps the screen can go dark on the only console such a laptop has, so that work comes first.

**Debugging without serial is cheap.** A phone photo of the screen and a log file on the stick cost nothing. Haiku saves an in-memory log across a warm reboot to a FAT volume ([Haiku](https://www.haiku-os.org/docs/userguide/en/bootloader.html)). A USB serial adapter costs ₹105 to ₹155 (Snippet, [Electropi](https://www.electropi.in/cp2102-usb-to-ttl-serial-converter-module)), but it helps only on a machine with a real serial header.

**Renting a laptop in India is possible, but not for the target.** No rental page listed Core Ultra Series 3 or Ryzen AI 300 or 400 machines ([Prime Asset Source](https://primeassetsource.com/categories/laptops/), [Techguru](https://techguru.co.in/rental/)). A 12th-generation i5 costs about ₹4,100 a month ([Rentorzo](https://www.rentorzo.com/)). With 18% GST (one seller quotes 5%) and a deposit of one to three months, plan on about ₹8,900 to ₹17,100 up front ([AssetShield](https://assetshield.co.in/blog/complete-guide-laptop-rental-india/), [Sirius Star](https://siriusstar.in/laptop-on-rent-india-cost-break-even/)). No provider publishes a rule on booting another OS, so get the lessor's written agreement first. Cyber cafes are out, because Indian rules require them to stop users from changing system settings (Snippet, [Cyber Cafe Rules](https://www.wipo.int/wipolex/en/text/494915)).

**Testbeds and grants are slow routes.** CloudLab and Chameleon are funded to September 2028 ([CloudLab award](https://api.nsf.gov/services/v1/awards/2431419.json?printFields=id,title,startDate,expDate,awardeeName,piLastName,fundsObligatedAmt), [Chameleon award](https://api.nsf.gov/services/v1/awards.json?pdPIName=Keahey&printFields=id,title,startDate,expDate,awardeeName,fundsObligatedAmt)), and CloudLab lists bare-metal nodes with current server CPUs ([hardware](https://docs.cloudlab.us/hardware.html)). Both require senior academic or research standing to lead a project ([CloudLab](https://docs.cloudlab.us/users.html), [Chameleon](https://chameleoncloud.readthedocs.io/en/latest/user/pi_eligibility.html)), so an individual needs a genuine research collaborator. Grants could pay for the declared machines. FOSS United made 2026 project grants from ₹1,05,000 to ₹8,00,000 ([FOSS United](https://fossunited.org/grants)), and FLOSS/fund gives up to $1 million a year to individuals and organisations ([FLOSS/fund](https://floss.fund/)). Buying is outside this report's limits, but §74 makes it necessary before any qualification.

**These facts are still unknown, and only a live test can settle them.** No custom UEFI image has been booted on any rented server or cloud VM in this research. Nobody knows yet whether a guest can actually enable shadow stacks on a runner, or whether the result holds on other runner CPUs. KVM on GitHub's Intel runners is unconfirmed. The Bochs CET build on an M1 is untested. Whether Google accepts a GPT-only image is untested. Whether Intel approves an individual, and whether `bm-ptl` is a laptop or a board, is unknown. The default boot mode, IOMMU state and serial port address on most rental machines are undocumented. Claims about any of these must wait for evidence (rule 14, §85).

## Conclusion

A result that passes only under TCG should now count for less. One free run showed costs that no TCG boot had shown. KVM on the runner is a better default for every kernel change, and TCG becomes the control.

Price is not the real barrier. A first real boot costs ₹30 to ₹116 of machine time. The barriers are an ID check, one kernel feature and a safe image. The owner's earlier decision that identity maps come before real hardware turns out to set the order of the whole plan. Without them, a video-only server or a volunteer's laptop can go dark with no way to see why. The one thing money cannot rent today is the target itself, so the volunteer image is not an extra. It is the only route to 2026 laptops without buying one.
