## 2. What exists

- **Processes** (`framekernel/src/process.rs`): an address space, a handle table, an account charging channels and queued bytes, the system-call range pin (A6), and teardown of the table when the last thread ends. A process is not a handle object: no ID, no `TERMINATED`, created only by kernel code.
- **Address spaces** (`framekernel/frame/src/userspace.rs`): private frames mapped only before any thread runs; at most 32 page-table frames; **the kernel half copied once at creation**.
- **System calls** (`framekernel/src/syscall.rs`): a hand-written dispatch over numbers 0–8; single-copy user memory with fault recovery.
- **Handles** (`handles.rs`): slot and generation values; rights only shrink.
- **Channels** (`channel.rs`, `ipc.rs`): the only object type. Messages carry no sender, and `channel_read` returns bare handle values.
- **Waiting**: `wait_one` on channels only, over the Loom-checked wait queue; deadlines accurate to a 10 ms tick.
- **ABI**: `origin-abi` holds the statuses, rights, signals, object types, numbers 0–10 (9 and 10 reserved) and a start-record codec the kernel never uses.
- **OIDL**: accepted; `origin.kernel.oidl` describes 11 calls; the generated code is not in the tree and the kernel does not use it.
- **Ring-3 proofs**: `user.rs::prove` and `ipc_proof.rs::prove`, driven by hand-written programs in `framekernel/frame/src/proof_programs.rs`.

**Missing**, by decision: P3's other objects (process, thread, memory object, event, port, timer); all of P6 (no start record, no creation calls, no Loader Service); all of P7; P8's sender identity; P9's `SIGNALED`, `TERMINATED`, ports and cancellation, and any way for a program to read the clock; P11's memory and thread quotas; Amendment 2 B1; Amendment 3 B3; ADR-0004 H2 (below); a §58 threat model of the system-call boundary.

**A latent defect:** ADR-0004 H2 requires the kernel's half of every address space to be tables allocated once at boot. Today the kernel half is copied when a process is created, so a kernel mapping made in a new top-level slot afterwards is missing from every existing process. It stays hidden only because proof processes end before PCIe and MMIO mapping. The first process that outlives the boot proofs (step 4) would meet it. Task S3-5a fixes it.

## 3. The tasks

Order: S3-0, S3-1, S3-2, S3-3, S3-4, S3-5b, S3-6. S3-5a may run alongside from the start, because it lives in the framework crate. S3-7 runs throughout. Shared interfaces (`origin.kernel.oidl`, `origin-abi`, `syscall.rs`, `ipc.rs`, `proof_programs.rs`, the boot markers) are changed by one task at a time (CLAUDE.md §78).

Every task: `cargo xtask check` and `boot-matrix` pass, and CI on KVM; no `unsafe` outside `framekernel/frame/`; the IPC leak check stays exact; every new boot proof has a negative control that fails the boot, and a row in ADR-0013's table; STATUS, TASKS and provenance updated; costs reported as QEMU figures with no budget (rule 21).

## 4. Interface changes

`origin.kernel` declares `version compatibility "user-abi"`, at 0.1. At major 0 a change to a recorded minor is reported, not refused (OIDL §9, §13), so each change re-records the fingerprint lock deliberately, citing Amendment 4. Additions carry `@since(0.N)`, one minor per landing. Call numbers continue from 11 and stay private to the release. New creation calls take an options `bits` from the start, because a system-call method cannot gain parameters within a major. (Superseded on 2026-11-10 by ADR-0005 Amendment 5, D1: a creation call takes its arguments in a sized request struct, which grows by P4's rule, and one with no argument yet takes none.)

| Change | In the interface |
|---|---|
| Handle records (B3, C3) | `channel_read`'s handles become `vector<received_handle>`, `received_handle {handle; object_type; rights}` |
| Identity (B1, C1, C2) | `read_sizes` gains `sender_process: u64` and `sender_principal: u64` after its 12 bytes |
| Events (C10) | numbers 9 and 10 lose `@reserved` and gain their errors |
| Default rights (C6) | new rights constants per object type |
| Start record (C4, C5) | plain structs `start_header` and `start_entry` and an enum `start_role`; the codec stays hand-written |
| Memory (C7, C8) | `memory_object_create`, `memory_map`, `memory_unmap`, `memory_protect`; a sized `map_request`; `map_access` and `map_flags` bits |
| Ports (C9) | `port_create`, `object_wait_async`, `port_wait`, `port_cancel`; a 32-byte `port_packet`; an enum `packet_kind` |
| Status (C11) | `not_found = -14` |
| Clock (C13) | `clock_read() -> (nanos: u64)` |
| Directory (C12) | a new library, `sdk/interfaces/origin.directory.oidl` |

## 5. Risks and dependencies

- **ADR-0012 and ADR-0013** land before step 3; every new boot proof needs a row in ADR-0013's table, and work touching `sched.rs`, `wait.rs`, `kernel.rs` or the boot markers starts after they land.
- **Scheduler and waiting**: 15 threads per processor and no migration; 16 waiters per wait queue; 10 ms deadline resolution; killing a blocked thread needs a framework call, so process termination by another process is out of scope.
- **TLB shootdown**: a global broadcast, one initiator at a time. User unmaps add shootdowns, so a hostile map and unmap loop must be charged or limited, and shootdowns should target only the processors with the space loaded. No shootdown while holding a lock another processor may spin on with interrupts off.
- **IOMMU**: `iommu::map` accepts only never-freed kernel DMA pages. Memory-object frames used by devices will need IOMMU pinning and an IOTLB invalidation before they are freed (the driver ABI's work); step 3 keeps them out of IOMMU domains.
- **No Rust in ring 3 before step 4**: proofs are hand-written programs, so the directory's logic is proven on the host.
- **CET** is not enabled; P6 asks for it at entry. A recorded deviation until CET lands.
- **Negative controls** are mostly hand edits recorded in prose; prefer controls that run in every boot, and Loom controls committed in xtask.

## 6. The first task

S3-0, in its smallest form: commit the generated types and server for `origin.kernel` in a kernel-private crate; make `framekernel::syscall` implement the generated `Calls`, converting at the boundary so `ipc.rs`, `handles.rs` and `channel.rs` do not change; add the freshness and fingerprint gates in a new xtask module; keep `origin-abi`'s public items, with a host test that they equal the generated values. Proven by the existing 117 hostile calls and every IPC and user-mode boot line passing unchanged, by three negative controls (the definition edited without regenerating; a `@nonzero` removed and regenerated, failing a boot line; a `Calls` implementation that skips a rights check), and by the ping-pong round trip reported before and after. It needs no owner decision, changes no ABI, and makes every later ABI change visible to the owner through its fingerprint gate.
