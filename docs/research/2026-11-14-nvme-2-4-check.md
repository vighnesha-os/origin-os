## 3. What matches

For every field the driver writes or reads, the offset, bit position, width and zero-based encoding match the three documents. In short:

- **Controller registers** (Base §3.1.4, pp. 78–93): the offsets of CAP, VS, INTMS, CC, CSTS, AQA, ASQ and ACQ; CAP's MQES, CQR, TO, DSTRD, CSS.NCSS, MPSMIN and MPSMAX; VS's three fields; the value written to CC (EN, CSS 000b, MPS 0, round-robin arbitration, no shutdown, 64-byte submission and 16-byte completion entries, CRIME 0, reserved bits 0), which is valid for every controller that offers the NVM Command Set and 4 KiB pages; CSTS's RDY and CFS; AQA's two zero-based sizes; ASQ and ACQ page-aligned. A 64-bit register as two aligned 32-bit accesses is allowed by the transport (PCIe §3.1.2, p. 9), and BAR 0 is mapped uncached.
- **Initialization order** (Base §3.5.1, pp. 131–132): reset and wait for RDY 0; the admin queue registers while EN is 0; enable and wait for RDY 1; Identify Controller; Identify Namespace; Number of Queues before any I/O queue; each I/O completion queue before its submission queue; MSI-X once the number of queues is known. A controller the firmware left shut down is handled by either of the two paths Base allows (p. 91; §3.6.1, p. 141).
- **Queue entries** (Base §4.1, §4.2, pp. 165–172): the submission entry's opcode, command identifier, namespace, PRP entries and command dwords; the completion entry's result, submission head and identifier, command identifier, phase and status, read with the phase dword first; the phase tag's flip at each wrap; one slot left empty in a full queue.
- **PRPs** (Base Figure 93, p. 168; §4.3.1, pp. 184–185): dword-aligned PRP1; PRP2 reserved within one page and the next page's base across one boundary; larger transfers refused.
- **Doorbells** (PCIe §3.1.2, Figures 4–6, pp. 9–11): their offsets from DSTRD, and none rung outside BAR 0.
- **Admin commands**: Create I/O Completion and Submission Queue (Base §5.3.1, §5.3.2, pp. 553–556), Identify (§5.2.14, pp. 362–366), the Identify Controller fields the driver prints (Figure 338), and Set Features Number of Queues (§5.2.30.1.5, pp. 491–492). Flush (§7.2, p. 593) covers the writes completed before it, and succeeds with no volatile write cache.
- **Interrupts** (PCIe §3.5, §3.8.4): one MSI-X vector per completion queue; every other table entry masked once the interrupt queue is set up. Before the independent review a table the firmware left on stayed as it was until then; since its F6 it is masked at bind.
- **NVM Command Set**: Read and Write's starting block and count (§3.3.4, §3.3.6, pp. 48–55); LBA Out of Range is generic status 80h (Figure 18, p. 25); the Identify Namespace fields NSZE, NLBAF, FLBAS and the LBA formats (Figures 123 and 125).
- **Timeouts**: Base defines no command timeout on PCIe and Keep Alive is not required there (§3.9, p. 155). After its own deadline the driver keeps a command's page out of use and its queue dead, which is what §3.4.5 (p. 131) says of a command that never completes.

### P1: a failure on CI that this check's work made explainable

On 2026-11-14, CI on pull request 38 (the kernel code of `land/s4-part2` at `e6fd12c`; an AMD EPYC 9V74 under KVM; the boot with no 8254 and no 8042) printed that the boot processor's per-CPU write did not read back, with 33 interrupts, and that NVMe failed. Read against the code: the DMA page's volatile stores, a `SeqCst` fence and the volatile doorbell are ordered on x86; the completion is read phase dword first, and the page after; nothing else used that processor's queue; and a lost interrupt alone cannot fail a command, since the wait looks at the completion queue before its deadline. QEMU's DMA fault in that log was the IOMMU proof's own unmapped probe page. A planted boot that gave the per-processor flush no time printed the same line. So a command that missed the driver's own 2 s deadline fits, most likely a flush waiting on the host's disk, as does a write that ended with an error status; the line could not say which. The fix: the driver's own deadlines (Flush 30 s, other I/O 10 s, admin 2 s; Base 2.4 sets no command timeout on PCIe, §3.9, p. 155), revisited when Abort or a controller reset is built, and every failure the driver detects named (`nvme::Fault`): on the per-CPU and interrupt-driven lines with the longest command's time, and on the block cache's failing lines. A command still outstanding when the boot flow judges its thread is named as still waiting, and the boot flow waits past the longest deadline its threads can meet (the independent review's F1 and F2). The cause on that run is not shown.

## 5. What revisions 2.0 to 2.4 changed on the driver's paths

From the Revision Changes document, as the check read it, each item checked against the 2.4 text where it touches the driver:

- **2.0**: CAP.CRMS, CC.CRIME and the CRTO register appeared. CRIME 0 is valid; CRTO was not read (M4).
- **2.1**: the Version register was redefined through a common descriptor with the same bit layout; Abort gained immediate and deferred forms and the Cancel command appeared (not used); MDTS may exclude metadata (L8); shutdown was clarified in a way that matches the driver's enable path; several "should"s on the controller's side became "shall"s (queue sizes checked against IOSQES and IOCQES, CQID checks, PC with CQR), all of which the driver already satisfies; the unique-attribute LBA formats and CNS 09h and 0Ah appeared (L4).
- **2.2**: changes to SGLs and Abort only; the driver uses PRPs and no Abort.
- **2.3**: an unsupported CC.MPS is undefined (the driver checks MPSMIN and MPSMAX); the admin queue size is a 12-bit field (32 fits); a non-zero CSI where a CNS does not use one may fail (the driver sends 0).
- **2.4**: queue identifiers are limited to the number allocated (the driver's are within it); the other technical proposals and errata are optional or touch features the driver does not use.
- **PCIe Transport 1.3 and 1.4, NVM Command Set 1.2 and 1.3**: nothing changes doorbells, PRPs, MSI-X, register access, Read, Write, Flush, LBA Out of Range or the Identify Namespace fields the driver reads.

## 7. Outside the three documents, not checked

- PCI Express Base rules for programming the MSI-X table, the command register and function-level reset. The driver's `pci` module cites PCI Express Base 6.x, which was not supplied.
- x86 memory ordering for the fence before each doorbell and for the order of reads from a completion entry (Intel SDM, AMD APM).
- What the IOMMU does with DMA to IOVA 0 (H1's effect on a metadata buffer): the VT-d and AMD-Vi documents.
