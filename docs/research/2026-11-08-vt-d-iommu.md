## 2. What QEMU 11.1's `intel-iommu` emulates

### 2.1 Capabilities (V2, `vtd_cap_init`)

- **CAP:** always `FRO`, `NFR`, `ND`, `MAMV`, `PSI`, `SSLPS`, `DRAIN` (read and write), `ESRTPS`, and `MGAW` = `aw-bits` − 1. `SAGAW` advertises 39-bit (3-level) and, with the default `aw-bits=48`, 48-bit (4-level) tables while `dma-translation=on` (the default). `CM` (caching mode) only with `caching-mode=on`. Not set: `RWBF`, `PLMR`/`PHMR`, `ZLR`.
- **ECAP:** always `QI` (queued invalidation), `IRO` (the IOTLB registers' offset) and `PT` (pass-through). `IR` and `MHMV` with `intremap=on`; `EIM` with `intremap=on` and `eim=on`; `DT` with `device-iotlb=on`; `SC` with `snoop-control=on`; scalable-mode bits only with `scalable-mode=on` or `fsts=on`. **`C` (page-walk coherency) is not set**, so the spec requires software to flush the CPU cache lines of every remapping structure it writes (§4, decision D7).
- **Defaults:** `aw-bits=48`, `caching-mode=off`, `scalable-mode=off` (legacy mode), `intremap=auto`, `eim=auto`, `dma-translation=on`. `eim=auto` resolves to **off** without KVM's in-kernel irqchip (`kvm_irqchip_in_kernel() && ir_supported`), so a TCG boot must say `eim=on`. No check refuses `intremap=on` or `eim=on` under TCG (only KVM's split irqchip has an extra check).
- **Register initial values:** `GSTS` 0; `FSTS` 0 with write-1-to-clear bits `PFO` (0) and `IQE` (4); `FECTL` 0x80000000 (fault events masked).

### 2.2 The DMAR table for q35 (V3)

- Header: host address width = `aw-bits` − 1 (47); flags bit 0 `INTR_REMAP` when `intremap` is on; **`X2APIC_OPT_OUT` and `DMA_CTRL_PLATFORM_OPT_IN` never set**.
- **Exactly one DRHD**, segment 0, register base `Q35_HOST_BRIDGE_IOMMU_ADDR` (0xfed90000), **flags 0 — `INCLUDE_PCI_ALL` is not set**. Its device scope lists:
  - the I/O APIC (scope type 3, enumeration ID = the I/O APIC's ID, on the pseudo bus 0xff); and
  - **every PCI device on every bus that does not bypass the IOMMU**, one scope each: type 1 (endpoint) or type 2 (bridge), start bus = the device's bus, a one-element path (device, function).
- No RMRR, RHSA, ANDD or SATC. An ATSR (all ports) only with `device-iotlb=on`.

So the parser must resolve devices through explicit device scopes, not only through `INCLUDE_PCI_ALL`. That is the more general path real firmware also uses.

### 2.3 Behaviour that decides the proofs (V2)

- **Global command:** `TE`, `QIE` and `IRE` act on a change; `SRTP` and `SIRTP` act whenever written as 1. `CFI` and `WBF` are ignored.
- **Register-based invalidation is refused while QI is on** ("Queued Invalidation enabled, should not use register-based invalidation"). This driver uses QI only (D6).
- **QI:** 128-bit descriptors unless scalable mode and `IQA.DW`; queue size 2^(QS+8) entries. Handled types: context cache (global, domain — treated as global — and device), IOTLB (global, domain, page with an address mask up to MAMV), interrupt entry cache (global and index), and the wait descriptor (status write of 32-bit data to the given address, and/or a completion interrupt). Reserved bits in descriptors are checked and a bad descriptor sets `FSTS.IQE`.
- **Translation:** a device whose context entry is not present faults with reason 2. A second-level walk checks the R/W permission at **every level** and reports a write to a non-writable (including not-present) entry as reason 5 and a read as reason 6; reserved bits in entries are reason 0xC. A context entry's level must be one `SAGAW` advertises; `TT` may be 0 (second-level translation) or 2 (pass-through), and 1 only with device-TLB support. An address above `min(MGAW, AGAW)` is reason 4.
- **IOTLB:** QEMU caches translations in an IOTLB keyed by source ID and page, so **a stale entry survives an unmap until it is invalidated**. That makes the unmap path testable: without the IOTLB invalidation, a DMA to a just-unmapped page would still succeed.
- **Fault recording:** one fault-recording register (`NFR` = 0) at offset 0x220 (`FRO` = 0x22). A fault is **dropped** if `FSTS.PFO` is set, or if a pending record has the same source ID (it collapses repeated faults), or (setting `PFO`) if the next record is still occupied. A recorded fault sets `F` and `PPF`, sets `FRI` when `PPF` was clear, and raises the fault event only when `FECTL.IM` is clear. Records: low qword the faulting page address (or, for interrupt faults, the interrupt index in bits 63:48); high qword `F` (63), `T` (62, set for reads), the reason (39:32) and the source ID (15:0). So a proof must clear stale records before it provokes a fault, and read its own record by source ID.
- **Interrupt remapping:** MSIs to 0xFEEx_xxxx are caught in every device's address space and remapped whenever `IRE` is on, **independently of `TE`**. With IR off, messages pass unchanged. **A compatibility-format message is passed through even with IR on: QEMU does not enforce `CFI`/`CFIS`**, so that protection cannot be shown under QEMU. Remappable messages: index = handle (address bits 19:5 and bit 2), plus the data's sub-handle when `SHV` is set (then data bits 31:16 must be 0). The IRTE is checked for the table size, present bit, reserved bits and **source-ID validation** (`SVT` 1: SID with the `SQ` mask; `SVT` 2: bus range), with reasons 0x21, 0x22, 0x24 and 0x26. With `EIME` the IRTE destination is the full 32-bit x2APIC ID; without it, bits 15:8 of the destination field. `IRTA`: size = 2^(S+1) entries, `EIME` bit 11, base bits 63:12; `SIRTP` also invalidates the interrupt entry cache.

### 2.4 virtio devices and the IOMMU (V4, V5)

QEMU gives a virtio device the IOMMU-translated address space **only with `iommu_platform=on`**; otherwise its DMA goes straight to guest memory whatever the IOMMU is programmed to do. With `iommu_platform=on` the device offers `VIRTIO_F_ACCESS_PLATFORM` (bit 33), and `FEATURES_OK` is refused unless the driver accepts it. So the boot uses `iommu_platform=on`, and the virtio-net driver accepts the feature and uses IOVAs; if a device does not offer it, the driver must give it physical addresses (virtio 1.1 §6).

## 3. Local experiments (M1 Max, QEMU 11.1.3, TCG)

- `-machine q35 -cpu max -smp 4 -device intel-iommu,intremap=on,eim=on` with an NVMe and a `virtio-net-pci,disable-legacy=on,iommu_platform=on` starts without error; so do `intremap=on` alone and `intremap=on,eim=on,caching-mode=on`. No `kernel-irqchip` option is needed (that is a KVM option).
- The baseline boot test (before this work) passes in about 27 s, 13 s of it the kernel boot.

## 4. Design decisions (detail in ADR-0007, Proposed)

- **D1. Legacy-mode translation first.** Root table → context table → 4-level (48-bit) or 3-level (39-bit) second-level tables, `TT` 0. It is QEMU's default and the smallest correct design; scalable mode (PASID tables, first-level tables) is a later step needed for SVA and PASID-granular isolation.
- **D2. Default deny.** Translation is enabled with **no context entry present**: until a driver attaches a device, its DMA faults (reason 2). Devices without a driver never get a context entry.
- **D3. One domain per requester ID** (bus/device/function), with its own second-level tables and domain ID (from 1). A device can reach only the pages its own driver mapped for it.
- **D4. IOVAs are not physical addresses.** Each domain allocates IOVAs from **[1 GiB, 2 GiB)**: below every PC platform's 32-bit MMIO hole (so not routed peer-to-peer), clear of the interrupt range 0xFEEx_xxxx, reachable by 32-bit DMA engines, and — under QEMU's 512 MiB — not backed by RAM, so a DMA that bypassed translation would land nowhere. Only the driver's DMA pages are mapped, 4 KiB each.
- **D5. Unmap invalidates and drains:** a page-selective IOTLB invalidation (domain-selective without `PSI`) with drain-read/drain-write where `CAP` offers them, then a wait descriptor; the page is reused only after that.
- **D6. Queued invalidation only.** It is required for interrupt remapping anyway; a unit without QI is reported and left alone.
- **D7. Coherency:** with `ECAP.C` = 0, every written root, context, paging and IRTE cache line is flushed (`CLFLUSH`, then a fence) before the hardware can need it; with `CAP.RWBF`, a write-buffer flush follows. With `CAP.CM`, not-present-to-present changes are invalidated too.
- **D8. Interrupt remapping with x2APIC destinations.** One IRT per unit (256 entries to start), `EIME` set when `ECAP.EIM`; every IRTE verifies its device's source ID (`SVT` 1, `SQ` 0); MSI-X entries carry only a remappable-format handle (`SHV` set, data 0), so the vector and destination exist only in the IRTE. `CFI` stays clear (compatibility-format interrupts blocked — on hardware; QEMU does not enforce it). With IR and EIM on, the MSI path accepts any 32-bit APIC ID: **the APIC-ID-255 refusal is lifted**.
- **D9. Faults are polled** from the fault-recording registers (fault events stay masked) and decoded by reason; a fault-event interrupt handler that feeds `klog` is a later step.

## 5. Tests defined before completion (CLAUDE.md §16.12)

- **DMAR parser (host):** valid tables of every structure type; every length, alignment and scope rule refused at its offset; device-to-unit resolution through endpoint scopes, bridge scopes (sub-hierarchies) and `INCLUDE_PCI_ALL`; a seeded mutation soak (never panics; anything accepted keeps its invariants).
- **VT-d encodings (host):** CAP/ECAP decoding against QEMU's documented values; root, context, second-level and IRTE encodings round-trip; the second-level walker maps, translates, refuses double maps and unmaps over an in-memory table store; invalidation descriptors and the wait descriptor; fault-record decoding; the remappable MSI address for every handle; the GCMD preserve rule.
- **Boot (QEMU, `-smp` 1/2/4):** the DMAR and the unit's registers reported; translation and IR enabled; NVMe and virtio-net pass every existing proof through their own domains; a DMA through a non-identity IOVA lands in the right physical page; after an unmap, a DMA to that IOVA is blocked (the target page untouched) and recorded with the device's source ID, the address and the reason; MSIs from both devices arrive only through IRTEs; an MSI through a not-present IRTE is blocked and recorded. Each with a negative control that fails the boot.
