## Checked and found sound

By reading, unless marked:

- **W^X is structural.** The access type has no writable-and-executable variant, and its readable and writable forms set NX.
- **Each page is mapped once, with its final permissions,** written through the direct map before any thread exists. Code is never writable, and RELRO is read-only from the start.
- **No mapping over a mapping, and none outside the user half.** Frames are zeroed.
- **`check` runs before anything is mapped** and holds what the launch relies on: slots strictly ascending, 8-byte aligned and inside the bytes of a writable or RELRO segment; segments aligned, apart and within the span; one read-execute segment that holds the entry. `fill_page` relies only on those rules; every access is bounds-checked and the base addition is checked.
- **Randomness.** Every draw goes through `origin_frame::random::next_u64`. With no generator the launch is refused before a child exists, and the proof is counted as not run.
- **Ranges.** Bases and stacks are page-aligned in `[0x1000_0000, 0x1000_0000_0000)`, apart from the start records' and `memory_map`'s range.
- **Nothing prints an address:** not the proof, the fault report or the debug calls.
- **Entry state.** RIP is the base plus the entry, RSP the page-aligned top of the stack, RDI the start record, every other general register zero, RFLAGS `0x202`.
- **The direction flag and the kernel.** The interrupt entry clears it and SYSCALL masks it, so a backward copy interrupted in the middle cannot run kernel code with it set.
- **CLAUDE.md §10.** No `bool` crosses an `extern "C"` or system-call boundary in the new code.
- **The host tool.** Every offset and size is range-checked, loops are bounded by the file, and the output depends on the input bytes alone.
- **In the built bytes:** `_start` clears RBP, aligns RSP to 16 and calls; `memmove` restores the direction flag on the one path that sets it; `thread_exit` is `syscall` then `ud2`; the five `mem*` functions are reached through RELRO slots.

Inferred and not verified: that a description the build writes always passes `check`. Nothing checks it at build time, only at each launch.

## Records that say more than the code shows

- **Threat row R1, "Proven (control R3-1)".** The control exercised the converter at build time, not the launch path. The clauses for the write to code, the jump into data and the write to RELRO have never been seen to fail.
- **R3.** The read-back uses the same slot list and addends as the writer, so it cannot see a slot the description lacks or a wrong addend.
- **R4, "Proven".** The control fixed the base only. The stack's half of the clause, and the refusal with no generator, have never been run.
- **R8, "Boot".** Only a good record is ever read; no refusal of a bad one is exercised.
- **STATUS and R6:** "between unmapped pages" and "stack never executable" hold by design only (F1).
- **`carried.rs`'s header:** "nothing in them comes from … a path" is true of the conversion, and the bytes carry a path from the compiler (F5).
- **The provenance entry** says the final gate results are in the hand-over report, which is not in the repository. The acceptance condition has no durable evidence there.
- **Row E11** (no CET shadow stack, though P6 asks for one) is recorded as an open deviation, and the kernel has none.
