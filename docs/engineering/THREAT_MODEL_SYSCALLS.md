## What is being protected

- The kernel's memory and control flow. No value from ring 3 may become a kernel pointer, an index past a table, or a jump target.
- Other processes: their memory, their handles and objects, and the messages queued for them.
- Rights. A handle never gains a right (P2), and a call does only what its handle's type and rights allow.
- The kernel's availability: its memory, the locks it holds with interrupts off, and the processors.
- Since S3-2, the truth of what a read reports: who wrote each message, and each received handle's type and rights.

## Who the attackers are

| Actor | Can | Today |
|---|---|---|
| A hostile ring-3 program | Run any instructions in ring 3, pass any register values, put anything in its own memory, and change that memory from another thread during a call | The main threat. Only the boot proofs' programs run in ring 3, created by kernel code |
| A hostile peer | Write messages and move handles to another process over a channel it holds, close its end at any time, never read | In scope |
| A buggy or compromised `origin.core` | Issue any call with any arguments from its own stubs | `origin.core` exists since task S4-2 and holds the generated stubs and nothing else (ADR-0011 L4), which the build checks on the linked image. The kernel does not trust it: every argument is decoded and checked as before, whatever the stub did |
| Code outside `origin.core` | Run `syscall` from its own pages, or jump into the middle of a stub | Stopped by the per-call pin (B2, G1) in every process `launch::load_program` makes: rows E7 and E8, and the section on `origin.core` below. The kernel's own proof processes keep a range (A6), and get a status |

**Out of scope:** a kernel already compromised another way, physical attacks, malicious firmware or microcode, and DMA (`THREAT_MODEL_IOMMU.md`). Speculative execution is listed as open (I2) but not modelled in detail. What each exclusion means for the product, where it is covered and what is accepted by name, is in `THREAT_MODEL_SYSTEM.md` (EX1 to EX12). Speculation is decided in `docs/adr/ADR-0017-speculation-processor-hardening.md`, which the owner accepted on 2026-11-10. Its Z1, Z2, Z3, Z5, Z9 and Z10 are built (TASKS item 19b); row I2 and the list under it say what that covers and what it does not.

## Threats

Status: **Proven** (a boot proof whose negative control is recorded in `SOURCE_PROVENANCE.md`), **Boot** (a boot proof, no control recorded), **Host** (host tests only), **By design** (no proof), **Partly**, **Open**.

### Entering and leaving the kernel

| # | Threat | Defence | Status |
|---|---|---|---|
| E1 | Another way in: `int n`, `sysenter`, or a 32-bit compatibility-mode `syscall` | `syscall` is the only entry besides faults and interrupts. Every IDT gate is DPL 0, so `int 0x80` from ring 3 is a #GP. `IA32_SYSENTER_CS` is zero, so `sysenter` is a #GP. The GDT has no 32-bit code segment, so there is no compatibility mode | **Boot** (the `int 0x80` program; "per-processor control state") |
| E2 | Ring 3 enters with TF, IF, DF, NT or AC set, so the kernel single-steps, takes an interrupt on the user stack, copies backwards or runs with SMAP off | `IA32_FMASK` clears all five on `syscall`. An interrupt from ring 3 with AC set is counted, and the `ac` program checks the count stays zero | **Boot** (`ac`, `step`) |
| E3 | An NMI or machine check arrives after `syscall`, before the kernel has left the user stack | NMI and #MC use their own IST stacks, with guard pages | **Proven** (M4's control) |
| E4 | A program confuses the kernel's GS base | `swapgs` on entry and exit; `CR4.FSGSBASE` is off, so ring 3 cannot set a GS base; the `gs` program loads a null GS and checks it survives | **Boot** |
| E5 | A return to a non-canonical RIP faults in ring 0 with ring 3's GS or stack (the SYSRET problem) | The kernel returns with IRETQ, and the top page of the lower half is never mapped, so a `syscall` cannot sit where RCX would be non-canonical | **By design**, host-tested |
| E6 | A return leaks kernel values in registers | Every register but RAX, RCX and R11 is restored from the frame. RAX holds the status, and RCX and R11 hold ring 3's own RIP and RFLAGS. The kernel is built without SIMD, and SIMD state is saved across switches | **Boot** (`regs`; "SIMD state across switches") |
| E7 | Code outside where the process may call from makes a call | Fixed when the process is made, never changed (ADR-0011 L8). A process pinned per call, which is every process `launch::load_program` makes: the thread is stopped and gets no status (B2; Amendment 8, G1). One of the kernel's own proof processes: refused with `access_denied` from outside the range its creator named (A6) | **Proven** for a pinned process (S4-2, control CP-1: with the pin's check out, a `syscall` in the program's own code is not stopped and the boot is refused). **Boot** for a proof process |
| E8 | Code jumps to the `syscall` instruction of one call with another call's number, so the stub's own load of its number is skipped | Closed for every process that is not one of the kernel's proof processes (task S4-2; ADR-0005 B2, G1; ADR-0011 L6 to L8). `origin.core` is naked stubs with one `syscall` for each number, held by a gate on the linked image. The kernel records where it maps `origin.core` in a process, and accepts call number *n* only if `rip − 2` is that base plus the offset of *n*'s own `syscall`; anything else stops the thread, and its ending records the number and the address. The proof processes keep their range, where this row stays open: they are made by kernel code alone, for the boot proofs | **Proven** (controls CP-1 and CP-4: with the pin's check out, or with a range over `origin.core`'s code in its place, the jump with another call's number is let through and the boot is refused). QEMU's software processor only. **By design** open for a proof process |
| E9 | A program uses the developer calls to hold the serial line with interrupts off | `debug_report` and `debug_write` need the `kernel.debug` capability, given only to proof processes; others get `not_supported`. A line is at most 128 bytes | **Boot** (`nodebug`) |
| E10 | A program reads the descriptor tables' addresses to find the KASLR slide | UMIP is on, so `sidt` and `sgdt` fault in ring 3 | **Boot** (`sidt`) |
| E11 | The CET shadow stack is not enabled, although P6 asks for it at entry | None | **Open**, a recorded deviation |
| E12 | **A nested NMI.** After an NMI is delivered, further NMIs are blocked until the next IRET executes, whoever executes it. If the NMI handler takes an exception of its own, that exception's return unblocks them while the handler is still on its stack. The next NMI enters through IST2, which loads the same top of stack every time, and overwrites the frame and the saved registers the first handler has yet to restore. The interrupted context is lost | None in the entry path: `exception_common` and `exception_saved` treat vector 2 like any other, with no mark that the handler is running and no second place for its frame. What keeps the window shut today is how little the handler does. For vector 2, `dispatch` records a count and the frame's address and returns: it reads no CPU-local data and no user memory, takes no lock and prints nothing. No breakpoint is armed (DR7 is cleared on every processor), and its code and its stack are always mapped. Two ways in remain. The kernel's own: a machine check during those instructions that `machine_check` judges recoverable returns with IRETQ. And one below the kernel: an SMI on an AMD processor, where the manual read does not say that NMIs blocked before the SMI stay blocked after it (Intel's says they do) | **Open.** Ring 3 cannot reach it: no call raises an NMI or a machine check, and the kernel's only NMI source is its own boot proof. The "NMI stack" proof behind E3 takes one NMI on IST2 and never two. FRED closes it where the processor has FRED; the path kept for processors without it needs a guard (ADR-0017 Z6 and Z12, accepted on 2026-11-10 and not built) |

### Arguments and user memory

| # | Threat | Defence | Status |
|---|---|---|---|
| A1 | A pointer names kernel memory, an unmapped page, or a page the kernel would write but ring 3 may only read | Checked against the calling process's own page tables (present, user, writable where written), then copied in a STAC/CLAC window with fault recovery. SMEP and SMAP are on and proven at boot | **Boot** ("bad pointers") |
| A2 | An address plus a length wraps, or a count times an element size overflows | `UserRange` refuses a wrapping or out-of-half range. The decoder checks each count against its bound before the multiplication, and no bound exceeds 64 KiB | **Host**, **Boot** ("sizes and numbers") |
| A3 | Another thread changes an argument between the kernel's check and its use | Every input is copied into a kernel buffer once, before it is checked, and nothing is read twice; `read_sizes.size` is read once | **By design** |
| A4 | A malformed scalar: out of range, an undeclared enum value or bit, a boolean that is not 0 or 1 | The generated decoder refuses it with `invalid_args` before the implementation runs (OIDL §7) | **Host**, **Boot** ("sizes and numbers") |
| A5 | An unknown or reserved call number | From a proof process: `not_supported`, without running any implementation. From a process pinned per call no stub has such a number, so the pin stops the thread before the dispatcher is reached (row E8) | **Host** for the dispatcher. **Boot** for both: a proof process asking number 999 is answered `not_supported`, and a pinned program with 9999 in RAX at a real stub's `syscall` is stopped ("origin.core and the call pin") |
| A6 | An implementation returns a status its call does not declare | Counted, the first recorded, and the IPC proof fails | **Proven** (S3-1 control 9) |
| A7 | A bad out pointer loses a message or the handles that came with it | Out pointers are checked before a message is taken. If a copy-out still fails, the handles installed for it are closed | **Boot** ("bad pointers") |

### Handles and rights

| # | Threat | Defence | Status |
|---|---|---|---|
| H1 | A forged handle: a value never issued, or one that is live in another process | Each process has its own table; anything else is `bad_handle`. Since task S4-0 a handle fills 64 bits and every register value goes to the table (ADR-0005 E1): the slot lies in the top 24 bits, so a value cut to 32 bits names nothing, and a slot at a generation never issued is refused | **Boot** ("bad handles": "its low 32 bits alone" and "its slot at a generation never issued"; S4-0 controls H64-1 and H64-2 in ADR-0013) |
| H2 | A stale handle names a slot that has been reused | A 40-bit generation per slot, since task S4-0 (ADR-0005 E1; a 16-bit one before). A slot whose generations are used up is retired, never reused; that takes about a trillion uses of one slot, so no process meets it in its life | **Host** (`handles.rs`: one slot past 2^16 uses, and one retired at its last generation); **Boot** ("bad handles": "stale, slot reused"; control H64-2) |
| H3 | A call runs with too few rights | The definition states the rights each handle needs, and the table enforces them on every lookup | **Proven** (S3-1 controls 1 and 2) |
| H4 | A handle of another type is used | The type is checked before the rights | **Proven** (S3-1 control 3) |
| H5 | A right is gained by duplicating or moving a handle | `handle_duplicate` only removes rights; a moved handle keeps the rights it had | **Boot** ("rights only shrink") |
| H6 | A handle is closed or moved away while a thread waits on it | The waiter is woken and completes with `canceled` | **Proven** (S3-1 controls 10 and 11) |
| H7 | A full handle table loses a message | Room for a message's handles is reserved before it is taken; a full table leaves it queued | **Boot** ("quotas") |

### Objects, quotas and lifetimes

| # | Threat | Defence | Status |
|---|---|---|---|
| O1 | A writer exhausts kernel memory through channels and queued messages | Each process is charged per channel and per queued byte, before anything is consumed. A queue holds 16 messages and 4 full-size messages of bytes | **Boot** ("quotas", "a writer over its byte quota", "its peer, unaffected") |
| O2 | Exhaustion through threads, processes or memory objects | No call creates threads or processes: for step 4 that is the decision (item 206, ADR-0005 G2), and the first call that creates either comes with its quota (G3, G4, drafts). A memory object is committed at creation and charged to its creator within the quota its own creator set, and each process's mappings are limited (M6, S3-5b) | **Closed for step 4 by absence** for threads and processes, reopening with the call that creates them; **Proven** for memory objects (M6) |
| O3 | A failed allocation panics the kernel | Everything a call creates is allocated fallibly and answered with `no_memory` | **Host** (allocation-failure test); no boot fault injection |
| O4 | Channel ends sent into each other's queues so that nothing can reach them, and memory is never freed (A3) | A transfer is refused for an end of the same channel, an end with other references, and an end whose chain of queues leads back. The walk stops at 16 links with `limit` | **Boot** ("transfers that would break the graph", "transfers into nested ends") |
| O5 | An object is used after it is freed, or leaked | Reference-counted objects; the IPC proof's leak check compares heap and frames exactly | **Proven** (S3-1 control 12) |
| O6 | `terminated` is raised before a process's memory is freed | The address space goes when the last thread is reaped, and `terminated` after it | **Proven** (S3-1 controls 4 and 5) |
| O7 | A process ID is reused, so a recorded ID names a later process | A 64-bit counter, never reused, 0 the kernel | **Proven** (S3-1 control 8) |
| O8 | A thread starts in a process that has already ended | One lock decides the last thread and refuses a late start. A thread is counted before it takes the address space | **By design** |

### Availability

| # | Threat | Defence | Status |
|---|---|---|---|
| V1 | Long stretches with interrupts off | Calls run with interrupts on and take locks briefly. The global transfer lock's walk is bounded at 16 links. Copies of up to 64 KiB run with interrupts on | **Partly**: no measured bound |
| V2 | A ring-3 loop that never enters the kernel delays reaping and `terminated` on its processor | The timer preempts it, but reaping waits until the processor is given up | **Open** (S3-1's known limit) |
| V3 | A full wait queue | A thread that finds 16 waiters polls by yielding instead | **By design** |
| V4 | A deep call chain overflows a kernel stack | Each thread's kernel stack has a guard page, so an overflow faults instead of corrupting memory | **By design** |

| # | Threat | Defence | Status |
|---|---|---|---|
| I1 | Uninitialized kernel memory is copied out | Results are built in zeroed buffers, and the generated encoders zero padding (OIDL §5.2) | **Host** |

### What a program chooses that the kernel then indexes or copies with (ADR-0017 Z9)

Z9's rule: a lookup whose index, count or address comes from ring 3 goes through `origin_frame::nospec`. No lint can tell where a value came from, so this list is the record, and **each new system call adds its own to it.**

| What the program chooses | Where the kernel uses it | Through |
|---|---|---|
| A handle's slot | `HandleTable::get` and `remove` (`framekernel/src/handles.rs`): every call that takes a handle, and every handle a `channel_write` carries. Since task S4-0 the whole 64-bit register reaches the table (ADR-0005 E1), and the slot is its top 24 bits | `nospec::index` |
| The address of anything copied in or out | `UserSpace::copy_in` and `copy_out` (`framekernel/frame/src/userspace.rs`), after the range check: the only two places the kernel copies to or from a program | `nospec::user_address` |
| The address and length of any memory the kernel checks before it reads or writes it: every pointer a call takes | The walk of the space's page tables by the program's address (`UserSpace::checked` in `framekernel/frame/src/userspace.rs`, under `check_user`, `copy_in` and `copy_out`), a page at a time, after `UserRange::new`'s range check. Each page the walk visits passes the clamp, in the closure handed to `usercopy::check_mapped`; the length is not clamped by itself, since it only says how many pages are visited. So the walk before a copy is clamped as the copy is (the row above), and so is the check of a pointer `syscall.rs` validates before it consumes anything (`checked`, `check_user`'s only caller). Under the mask, a wrongly guessed path walks address 0: the space's own lower-half entries, which the program's own accesses walk anyway | `nospec::user_address`, once for each page |
| The length of `debug_write`'s text | The copy into a buffer on the kernel's stack (`syscall.rs`, `debug_write`) | `nospec::length` |
| The number of handles a `channel_write` carries | The copy into `raw` and the list read from `values`, both on the kernel's stack (`syscall.rs`, `channel_write`) | `nospec::length` |
| The `size` a reader writes in its `read_sizes` record | The piece of the encoded record copied out (`syscall.rs`, `channel_read`) | `nospec::length` |
| The `size` of the request record `memory_object_create` and `memory_map` read | The copy into a buffer on the kernel's stack (`syscall.rs`, `copy_request`) | `nospec::length` |
| A `memory_map` request's offset and length | The object's frames the mapping takes (`memory_object.rs`, `MemoryObject::run`), and by the same count a random place and a take-back. Clamped where the range is checked (`mapping.rs`, `check`), the only place a request becomes pages | `nospec::length`, twice |
| A `memory_map` request's fixed address, and the address and length of `memory_unmap` and `memory_protect` | `UserSpace::map_shared_run` makes and fills page-table entries by the address it is given (`prepare_user`, `map_user`). `unmap` and `protect` compare the address and its end with the space's own sorted records and walk the tables by each record's address, so for them the clamp guards a comparison; it is kept so that every address a program gives passes `nospec` before the address space is asked. The address is clamped twice. In the kernel before the call (`mapping.rs`, `user_run`): by `check` for a fixed address, and by `memory_object.rs`'s `unmap` and `protect` before they ask the records for the mapping. And in the framework (2026-11-11): each of the three passes its address through `nospec::user_address` right after its range check (`user_range_end`), whatever the caller, so a caller added later cannot leave it out. The framework clamps the address and not the count, or the end it computes from the two, so the count's clamp is the kernel's alone | `nospec::user_address` and `nospec::length` in the kernel; `nospec::user_address` again in the framework |
| The call number | The generated dispatcher's `match`: comparisons, with no table (the image gate holds that). A wrong guess among them runs another call's decoder on this call's arguments, and that decoder's lookups are in this list | Not an index |
| The call number, in the per-call pin (task S4-2) | The generated `pinned`, inside `pin::judge`, in `syscall::pin_verdict`, a function the kernel never inlines: a `match` on the number whose arm compares the call's offset with that number's own. Comparisons, with no table: the offsets are constants of the kernel's image. The image gate reads that function on every build and fails unless one register is compared with every offset as an immediate, with no indirect jump and no memory operand indexed by a register before its first call (the review of 2026-11-13, K4). As compiled, the search on the number is the dispatcher's own. A wrong guess among the arms accepts a call from another stub's address on the guessed path, which is what a wrong guess in the dispatcher already does (the row above) | Not an index |
| The address the call came from (`rip`, from the `syscall` instruction) | The pin subtracts 2 and the process's recorded base, both wrapping, and compares the result with a constant (`pin::judge`, host-tested at 0, 1, the top and below the base). It is never dereferenced and never an index. For a proof process it is compared with the two ends of its range | Not an index |

Looked at and left alone, because the value is the kernel's own by the time it is used: the lengths `copy_out_handles` and `copy_out_records` take (set when the message was written, within the limit checked then); the size of `channel_write`'s payload, which sizes the buffer it is copied into; rights, signals and deadlines, which index nothing.

Looked at and left alone in the seven event, port and clock calls (2026-11-11), because nothing is indexed by them: a binding's key is compared and never used as an index; the masks and the deadline are compared; a packet is written at the definition's fixed offsets, and the clock's value through `copy_out`; a port's index is indexed by slot numbers the kernel gave when the binding was made, never by a value a program chose; each handle goes through `HandleTable::get`, as every call's does.

Looked at and left alone in the four memory calls (2026-11-11), because nothing is indexed by them: a mapping's record is found by comparing each record's address and pages with the ones asked for, in a list the kernel made; access and flag bits are compared; `memory_object_create`'s length sizes the kernel's own new object and is charged to the account's quota first; a random place is the kernel's arithmetic on the clamped count; a change's price is arithmetic; and the generated decoders read fixed offsets of a full-size buffer, where `size` only says by comparison which fields are present.

### A message's writer and handle records (S3-2)

ADR-0005 B1 and B3, as C1–C3 decide. The ledger is `docs/research/2026-11-10-caller-identity.md`. "Proven" here means the boot proofs "a message's writer" and "IPC and handles", with the controls recorded for S3-2 in `SOURCE_PROVENANCE.md`.

| # | Threat | Defence | Status |
|---|---|---|---|
| W1 | A writer forges its identity | `channel_write` stamps the message with the writing process's identity, which never changes, and queues the two together. No argument carries it | **Proven** (controls 4, 5) |
| W2 | The identity is stale: it names whoever held the end when the channel was made, or holds it when the message is read | Each message is stamped when it is written, and keeps its stamp while its end moves | **Proven** (control 6) |
| W3 | A recorded process ID comes to name a later process | IDs are never reused (O7) | **Proven** (S3-1 control 8) |
| W4 | Only part of a 64-bit field reaches the reader | Both fields are 64 bits end to end, and the proof's values have both halves set | **Proven** (control 9) |
| W5 | A reader that gives an older `size` has memory written past it | The kernel writes only what fits in the caller's `size`; the first version's 12 gets the counts and nothing past them, with no error | **Proven** (control 8) |
| W6 | A read too small for its message hides who wrote it, so a reader must take an unwanted message to learn its writer | The identity is written on `buffer_too_small` too | **Proven** (control 7) |
| W7 | Identity is taken for authority | A process ID or principal names nothing and opens nothing (P1, C1). Acting on the writer needs a handle the writer gave | **By design** |
| W8 | A relayed message names the relay, not the first sender | Intended: the stamp is the last writer. A relay that vouches for an earlier sender says so in its own protocol, and the reader trusts that only as far as it trusts the relay | **By design** |
| W9 | A received handle's type or rights are misreported, so a receiver trusts a handle it should not | Each record is made from what the reader's table now holds for the handle | **Proven** (controls 2, 3) |
| W10 | Records are written past the caller's buffer | Room for whole 12-byte records is checked before a message is taken | **Proven** (control 1) |
| W11 | A record or `read_sizes` value outside the definition reaches a client as a value | The generated client decodes each record and the sizes checked; an undeclared type, right or padding byte is a protocol error | **Host** |
| W12 | The writer's principal tells the reader more than it should | Intended: B1 delivers it. Principals are opaque numbers the creator chose; what they may encode is for the accounts design (§57) | **Open**, with I3 |

### Process start (S3-3)

ADR-0005 P6, as C4–C6 decide, and C1's inheritance of the principal. The ledger is `docs/research/2026-11-10-start-record.md`. Written before the code (§58, §83), then given the status the boot proof "process start" and its controls (recorded for S3-3 in `SOURCE_PROVENANCE.md`) earned.

| # | Threat | Defence | Status |
|---|---|---|---|
| P1 | A child acts for a principal its creator chose instead of the creator's own, so per-user policy and audit name the wrong user (C1) | The launch path reads the principal from the creator and takes none of its own; no capability to choose another exists | **Proven** (control 3): the message each child writes on BOOTSTRAP names the creator's principal (B1) |
| P2 | The process changes its start record, and code that reads it later trusts what the process wrote | The record's pages are mapped read-only and not executable | **Proven** (control 1): each child's write to its record faults at the record's address |
| P3 | The record sits where an attacker can predict it | A random page in the upper user half, drawn from the kernel's random-number generator (`origin_frame::random`, ADR-0016; task 18b, in the batch since `c2245ef`, 2026-11-11), clear of every other mapping. With no generator no process is launched, rather than one at a predictable address, and the boot says so | **Proven** (control 5): two launches place their records at different addresses. **Not shown** by any boot: a launch with no generator, since QEMU's processors have the instructions it is seeded from |
| P4 | The record carries kernel memory or stale bytes | Fresh zeroed frames, an exact size and zero padding, from the `origin-abi` encoder | **Boot**, **Host**: the record each child reads back decodes with `origin-abi`'s decoder, which refuses a wrong size or a non-zero padding byte; host tests of both |
| P5 | A start handle has more rights than C6 gives its role | Each role's rights are fixed in the launch path: C6 for the process and thread, a channel's for BOOTSTRAP and DIRECTORY | **Proven** (control 4): each entry's rights read back in ring 3 |

### `origin.core` and the per-call pin (S4-2)

ADR-0011 Amendment 2, L2 to L8, and Amendment 3, L13; ADR-0005 B2 and Amendments 8 and 9 (G1, H1). `origin.core` is the kernel's only door for a program: one image a release, the generated stubs and nothing else, carried in the KRN image until the Loader Service exists (M6). The launch path maps it into each program's process on one set of frames and binds the program's imports to it; the kernel accepts each call only from its own stub. Written with the contract (TASKS item 47), then given the status the boot proofs "origin.core and the call pin" and "the flags at a thread's entry" and their controls (ADR-0013, CP-1 to CP-8) earned. Everything here has run under QEMU's software processor on the development Mac and nowhere else.

A mapping holds its object, so the charge returns only with the last handle and mapping. Each process holds at most the mappings its creator allows. A space's page tables are bounded too (the framework's `MAX_TABLES`, T40): a map that needs a table past the bound is refused with `limit` when its place is free (a taken place is `invalid_args` first, M2), and one that finds no free frame, or no room in the kernel's heap, with `no_memory` (D4, the owner's item 142). Either way none of its pages is mapped and no record is left | **Proven** (controls 8, 9 and 18): past the committed bytes and past the mapping limit, refused in ring 3; a closed object still mapped keeps its charge; nothing is owed once the process has ended. **Proven** by the kernel's own calls (control 25): mappings 2 MiB apart until one needs a table past the bound; it gets `limit`, leaves no page and no record, and a page in a table the space has is still mapped. **Host**: the quota and the limit to the unit; each refusal's status (`a_refused_run_has_the_status_of_what_refused_it`, control 23). **Not shown** by any boot: `no_memory` from `memory_map`, which needs a machine out of frames; a refused run may leave empty tables behind, which count against the space's bound until the space goes |

| M8 | A hostile map and unmap loop interrupts processors or holds the shootdown turn (T15, T16) | A budget of shootdowns and interrupts per process, refilled with time at a rate its creator sets. An unmap or protect is priced before it runs, from its pages and `processors_loaded`, and refused with `should_wait` if the budget cannot pay, before any change or turn; afterwards its `Change` is charged. No rate makes a unit free: one above a unit a nanosecond counts as a unit a nanosecond, so the burst always bounds what is spent at once. A map itself is not priced, because it interrupts no processor and takes no turn: its pages are entered in one call, all or none, and a refused run was never entered, so there is nothing to unmap after it and no shootdown (`UserSpace::map_shared_run`, T39; review finding B). A map taken back because its address could not be reported (M16) is not priced first; it is charged afterwards | **Proven** (controls 12, 13 and 14): H's loop is refused with `should_wait` once its budget is spent, with its mapping still there, and served again once the budget has refilled. **Proven** (control 20): a map taken back is charged. **By reading** for a refused map: `put` has no unmap on that path; that no entry of a refused run was ever present is the framework's contract and its boot proof (T39). **Host**: the rate's bound (`no_rate_makes_a_unit_free`, control 21). **Open**: a map taken back is a shootdown the budget did not agree to beforehand, as large as the mapping (M16). **Step 4**: the call that lets a creator set a rate must say what a rate above 10⁹ a second means to its caller; the kernel takes it as 10⁹ |
| M9 | A mapping placed where an attacker can predict it; or a search for a free place that does not end, or that ends with a status that sends its caller looking for memory | A random page drawn from the kernel's random-number generator (`origin_frame::random`, ADR-0016; task 18b, in the batch since `c2245ef`, 2026-11-11), clear of every mapping; when the generator gives no number the map fails with `not_supported`. A draw that lands on something mapped is drawn again, eight draws at most (`mapping::place_at_random`). Eight taken places in a row are `limit`: a bound of the process's own address space, while `no_memory` stays for frames and the kernel's heap (ADR-0005, the notes on D4 and D5; the owner's item 156). The generator refuses in two ways, and the map folds both into `not_supported`: `NoGenerator`, none was seeded at boot, which is permanent and the case D5 means; and `NotNow`, which passes. So a program would read a passing refusal as a lasting one. No ordinary path to `NotNow` from a system call was found: it needs an NMI or a machine check that enters the generator in mid-step, or a generator at its request limit whose reseeds keep failing. A map no longer makes the kernel draw RDSEED or RDRAND: the generator stands between, and the instructions are drawn only at its reseeds, so ring 3 cannot make the kernel draw the processor's entropy at will | **Proven** (control 6) that two placements are apart and in their region. **Host** (control 27): `eight_taken_places_in_a_row_are_limit`, eight draws, each one tried, and no ninth; `a_random_place_is_drawn_until_one_is_free`, which also shows a draw that gives no number answered `not_supported` with nothing tried. That placements cannot be predicted rests on the generator (ADR-0016; **By design**). **Not shown** by any boot: the map with no generator, since the memory-object proof cannot run on a machine with none (TASKS item 37 (d)); `NotNow`; and a draw that lands on something mapped, which the region's 6 × 2³² pages make rare |
| M10 | An object shows kernel memory or another process's | Its frames are zeroed at creation | **Boot**: H reads zero from its new object in ring 3. The zeroing is the framework's (`SharedFrame::new`) |
| M11 | A frame is freed while it is mapped, or an object outlives its charge | Each mapped page holds its frame (`SharedFrame`), each mapping its object, and the object its charge; each goes with its last reference | **Proven** (controls 7, 9 and 15): memory released under a live mapping is caught by the reader that keeps its mapping; a charge kept past its process, and a frame kept past its object, by the proof's own lines and its leak check |
| M12 | Closing a handle unmaps another process's memory, or a mapping outlives its process | A mapping holds its object, so a close never unmaps; a process's mappings go with its address space when its last thread ends (P11) | **Proven** (controls 7 and 9): B still reads through its mapping after closing the handle; a process's mappings go with it when it ends |
| M13 | A request changes between its check and its use | `map_request` is copied once, its `size` checked first (OIDL §5.3), and decoded from the copy | **By design** |
| M14 | A stalled shootdown is reported as a success, or `timed_out` is returned for a change made only in part (review finding A, 2026-11-10) | `memory_unmap` and `memory_protect` return `timed_out`, and it means what D5 says: the change is made. The framework finishes a change whatever stalls (T3): after `ChangeError::Stalled` every page of the range has its final entry, so the kernel removes the mapping's record, or gives it its new permissions, as for a change that completed. The frames a processor may still reach are kept from reuse (T3), and the space's next change flushes it first (T26). The price paid beforehand stays paid and nothing beyond it is charged, since no cost comes back with a stall. A map taken back (M16) reads a stall the same way and, having paid nothing beforehand, is then charged nothing | **Modelled** in the framework: T3's two Loom models of a change whose round, or whose first flush, stalls, with their controls. **By reading** for the kernel's arms in `unmap`, `protect` and `withdraw`. No boot can stall a processor |
| M15 | The bookkeeping done with interrupts off grows without bound (T18) | Each process's mappings are limited; `MAX_TABLES` is not raised | **Partly**: each process's mappings are limited (control 18) and `MAX_TABLES` is not raised; the kernel's own map, protect and unmap of 16 pages take tens of microseconds under QEMU (S3-5b's figures in `SOURCE_PROVENANCE.md`), with no budget |
| M16 | A mapping stays in a space though its caller was never told where: the write of its address fails (review finding D, 2026-11-10) | The address is written while the mapping's record is still reserved, so no other call can change the mapping first. If the write fails, the mapping is taken back whatever the caller's budget holds, the call fails with the write's error, and no result is written (`address` has no `@also_on`). What taking it back cost is charged to the caller afterwards. The pointer is checked against the caller's page tables first, so the write fails only if that page is unmapped or made read-only between the check and the write, which is itself a priced change | **Proven** by the kernel's own calls (controls 19 and 20): with a report that fails, no page and no record are left in a process whose budget pays for nothing, and the next unmap of a process that could pay must wait. **By design** for the system call's own write: ring 3 cannot make it fail at will, and no boot does. **Open**: one priced change of one page can bring a shootdown the size of the mapping taken back, paid for only afterwards; the caller's budget bounds how often, not how large. Holding the page the address goes to before mapping would leave nothing to take back; that needs a framework call. The take-back reads a stalled shootdown as `memory_unmap` does (M14): every page is out of the tables and the record goes. The space refuses an unmap otherwise only for a range it cannot have, before anything changes, which a mapping's range never is; were that arm reached, the mapping would stay as an ordinary mapping of its process, which goes with the process at the latest |
| M17 | A change to a mapping that another call is making or changing at that moment is told there is no such mapping (`invalid_args`), so its caller forgets an address that is still mapped; or the refusal changes or spends something (ADR-0005, the two notes on D5; the owner's items 155, 163 and 164) | `memory_unmap` and `memory_protect` return `should_wait` for a mapping whose record is busy: one whose map has not written its address yet (M16), or one another unmap or protect holds. The record is not taken and stays as it was, and no page-table entry changes. Nothing is spent: the mapping is asked for before the budget is, and in `memory_protect` before the access is compared with what the mapping allows, which is not settled while another call changes it. A range that is not exactly one mapping is `invalid_args`, busy or not (M3). A retry takes the mapping or finds it gone. A mapping is busy only while one call maps, unmaps or protects it, and each of those ends, a stalled one with `timed_out` (M14). A caller that retries in a loop spends its own system calls and nothing else: each takes the records' lock for one look, and interrupts no processor | **Proven** by the kernel's own calls (controls 26, 28 and 29): an unmap and a protect made from inside a map's report, and of a record the proof holds as a change holds it, each get `should_wait`; the page stays on its frame and the record as it was; and a budget of one unit still pays for the mapping's one unmap. **Proven** the same way (control 32): a protect that asks for more than a read-only mapping allows gets `should_wait` from inside the map's report and while a change holds the record, and `access_denied` once the record is free, with the budget empty throughout. **Host**: `a_mapping_another_call_is_changing_says_wait` (control 26). **Not shown** by any boot: two ring-3 threads racing on one mapping. The proof holds the record itself, through the calls the system calls make |

### Events and ports (S3-6)

ADR-0005 C9, C10 and C13, as Amendment 7 decides them (F1–F19): `event_create`, `object_signal`, `port_create`, `object_wait_async`, `port_wait`, `port_cancel` and `clock_read`. The protocol of bind, raise, cancel and close is the framework's (`origin_frame::sync::ports`, task S3-6a), whose host tests and Loom models are its own evidence; the kernel's side is `framekernel/src/port.rs`, `event.rs`, and the hooks in `ipc.rs` and `process.rs`. The ledger is `docs/research/2026-11-11-events-ports.md`. Every boot result named here runs under QEMU on the development Mac only.

## What must be closed

Before any program that is not a boot proof runs in ring 3 (N14 step 4):
1. **E8**, the per-call pin (Amendment 2, B2): **built by task S4-2**, as items 202–205 decide it (ADR-0011 L6–L8, ADR-0005 G1), for every process `launch::load_program` makes, with its boot proof and controls CP-1 to CP-8. Seen under QEMU's software processor only; an independent review of it is to come. The kernel's proof processes keep A6's range.
2. **O2**: closed for step 4 by absence, since no call creates a thread or a process (item 206, ADR-0005 G2). It reopens with the first call that does, which comes with its quota (P11; G3 and G4 are drafts). Memory's are built (M6, S3-5b).
3. **I2**: a speculative-execution review against the declared processors. The review is `docs/research/2026-11-10-speculation-processor-hardening.md`, and ADR-0017, accepted on 2026-11-10, decides from it. Its Z2, Z3, Z5, Z9 and Z10 are built (task 19b), and boot under QEMU's software processor and as KVM guests in CI, neither of which offers the controls. **I2 stays Partly until a boot on a processor in the declared scope shows each one read back as written** (item 213, matching the system model's row for a program that is not first-party). CI's KVM boots cannot be that boot: on 2026-11-11 their guests, on an AMD EPYC 7763 and an Intel Xeon Platinum 8573C, offered none of the controls. **Step 4 goes ahead with I2 Partly** (item 213, ADR-0011 L9): its programs are first-party and run under QEMU and as KVM guests. I2 must close before any claim about real hardware, and before any program that is not first-party runs in ring 3.
4. **D11**, the directory's back side: decided (items 211 and 212, ADR-0005 G7 and G8), and built before the first directory that is a program runs.

Before any claim about real hardware: **E12**, the nested NMI.

Before release: **E11** (CET) and **V2**.
