## Checked and found sound

By reading, unless marked:

- **The one new `unsafe` block (`vm::grow_stack_region`).** Its SAFETY argument holds. `allocate_run` marks the run allocated, and nothing frees it or makes an `OwnedFrame` of it. Allocatable frames are usable RAM, all in the direct map, which is linear, so a physically contiguous run is a virtually contiguous slice. The trampoline's two frames are excluded from the allocator at boot (`early.rs`), so the first-fit scan from frame 1 cannot take them before `prepare` writes them. Each table is zeroed when the pool hands it out (`Run::allocate_table`), and the pool returns only tables below `used`. `extend` refuses a run overlapping the first and a second extension. The slice is `'static` and never freed. No shootdown is needed: the entries filled were not present, and no AP runs yet (growth precedes the park drill). The kernel half's PML4 entries were made at boot, so every address space sees the new tables. A failure leaves only harmless reserved tables, and the region at its floor.
- **`PerCpu`.** Safe code (`forbid(unsafe_code)`). The slice is filled before `SetOnce::set` publishes it (Release), readers take it with Acquire, and it is leaked, never moved, resized or freed. Index 0 is the static boot slot; every other lookup is `slice::get`. Sizing runs once (`swap`), and a failed reservation leaves the table at index 0 alone. An AP that somehow saw the table unpublished would fall to `OUT_OF_RANGE` and be refused, not read past it.
- **Order in `smp::start`.** MADT, then the framework's tables, the kernel's tables, the region's growth, then `fix_count(min(reached, room))`, then APIC IDs assigned, the trampoline, the drill and the starts. `count()` is at most every sized table's length and the region's room. `to_start = min(started, count)`, and the starts iterate `take(to_start)`, so online-capable indexes are never sent INIT. `complete` is false when an enabled processor is held back or a table was sized twice, so loader memory is not reclaimed, and the boot test, which requires the `origin-kernel: reclaimed` line, fails even though ": per-CPU sizing failed" is no failure marker.
- **`CpuIndex`.** Made only by `new` (checked against `count()`), `BOOT` and `this_cpu`. `OUT_OF_RANGE`'s `u64::MAX` resolves to `None` in every table. `tlb::send_ipi` re-checks through `CpuIndex::new`.
- **Ring 3 reaches no processor index.** `syscall.rs` and `framekernel/syscalls/src` name none; every `launch::start`, `start_program` and `Process::start_thread` caller is a kernel proof choosing its own processor; the NVMe and virtio-net `CpuIndex::new` calls only format a report.
- **MADT parsing.** Each entry's length is at least 2 and bounded by the table; type 0 needs 8 bytes and type 9 needs 16; the buffer is `len / 8` entries, so `TooManyProcessors` cannot arise; duplicates are dropped; the broadcast ID gets no index; the boot processor is index 0 whether or not listed. The layouts and flags match ACPI 6.6 Tables 5.22, 5.23 and 5.34: Enabled is bit 0, Online Capable is bit 1 and only meaningful with Enabled clear, and type 9 shares the flags. Reading bit 1 only from MADT revision 5 is conservative.
- **The shootdown's change.** Marks are touched only by the turn's holder, set and cleared under the same turn, and cleared on every path, the stall included. A must-answer processor with no mark is a stall. The count is read after the fence. Otherwise the protocol is the old one. The Loom models run the same generic code over `Held`. A control whose text is missing fails `cargo xtask loom` loudly (`apply` requires exactly one match), so no control can pass by not applying.
- **`Slots::grow`.** Storage is allocated outside the lock; `Already` and `NoMemory` change nothing; the `first_free` invariant holds, since new slots are above every old one; every accessor handles indexes past `N`.
- **The region's layout.** The 1 TiB reserve lies inside PML4 slots 384 to 447 for every drawn base (31 × 2^19 placements). The floor's tables are made at boot and the growth's from `base + 256 MiB`, 2 MiB-aligned. Every slot keeps its unmapped space below its stack. `in_stack_region` and `slot_of` read `region_size()`, which is stored only after the slots exist. The base is never printed.
- **NVMe arithmetic.** `asked` is clamped to `u16`; `wanted >= 2`; `sqs, cqs >= 2` is checked, so `pairs - 2` cannot underflow; `qid` stays within `u16`.
- **The boot checker's per-line rewrite** fails every line it failed before. It judges the complete lines at each chunk that holds a newline, which is every point at which a new complete line exists, and once more on timeout and on disconnect. Only the oversubscribed path differs, and only by the scheduler's fair-share lines, and only under TCG.
- **Arithmetic.** Every division by a count or a rate is guarded (`max(1)`, `checked_div`); the region's size cannot overflow (processors clamped to 262,144); the casts are within range.
- **`percpu-gate`** refuses `MAX_CPUS` by token and excludes test-only items correctly, `not(...)` and `any(...)` included (within F2 and F10's limits).

## Records that say more than the code shows

- **STATUS and TASKS 58's result, "A machine short of memory for its tables: host-tested."** Only `largest_fitting`'s search is host-tested, with a fake predicate. Nothing tests `size_with` with a failing allocator, `Sizing.reached` falling, or `smp::start`'s count and "held back" line under a memory shortage; AC-5 covers the region bound only.
- **ADR-0008 "As built" D3 and the contract's invariant (5), "a processor that cannot get its tables or stacks stays in firmware, counted and named."** Its stacks, yes; its `CpuTables` and `ApStart` boxes panic the kernel on exhaustion (F8).
- **Threat row T43, "a processor with no record cannot mark itself online."** True of the protocol. Such a processor would still run, schedule and switch spaces without being a shootdown target (F2, F6). The protection is the sizing order alone.
- **ADR-0013's entry, "Unchanged: machines of 1 to 4 processors stay at 2×."** Only on a host with at least 4 threads (F9).
- **STATUS, "the 67-processor sparse machine, with APIC IDs 256, 300 and 412 above 255."** Those three come online, take IPIs and run threads, but no device interrupt reaches them on that machine (F1). No record says so.
- **ADR-0008 "As built" D6, "The IOMMU proof's routes are those it programmed."** Those a fully successful setup programmed (F4).
- **ADR-0008 "As built" D1 and matrix row A08-D1, "`cargo xtask percpu-gate` refuses a table it leaves out."** Lexically: an alias, a struct field or a non-call mention passes (F2). Row A08-D5 names the gate's spelling limit; A08-D1 names none.
- **The hand-over note, "every `CpuIndex::new` caller is inside the kernel (`tlb.rs`, `smp.rs`, and the NVMe and virtio-net drivers' interrupt routing)".** The driver calls format a report and route nothing. The conclusion, that no ring-3 path reaches an index, holds.

The contract's invariant (9) deviation (the `unsafe` block in `vm.rs`, not `percpu.rs`) is recorded plainly in TASKS, the hand-over and the provenance entry, and `vm.rs` is a listed file, so CLAUDE.md §13 holds.

| N1 | Medium | **F1's order makes the NVMe per-CPU proof fail on any machine with an APIC ID above 255 and no interrupt remapping, and storage is then withdrawn.** Drivers bind with direct DMA when the platform has no IOMMU (`pci::dma_path`, `IommuStatus::Absent`), for example with VT-d turned off in firmware setup.
