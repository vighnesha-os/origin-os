## Medium

| ID | Finding | Answer |
|---|---|---|
| R97-1 | The tree was indexed by position in `online.cpus()`, not by CPU index: after an AP that did not start, every later name is shifted, in the printed tree and in `DOMAINS`, which items 98 and 100 read | **Fixed.** `domains::Processor` carries its CPU index; `Tree::cpus()` keeps them in the input's order; a level prints its groups by CPU index, and `Domains::capacity` is documented in `tree.cpus()`'s order. Host test `the_tree_names_processors_by_their_cpu_index`: the SMT machine without CPU 3 prints `core, L2 4 groups [0-1\|2\|4-5\|6-7]` |
| R97-2 | xtask's `domain_tree` ignored the planted PPTT, so where the guest reports no cache leaf (an AMD guest, or KVM without `topoext`) it expected no cache level while the kernel, rightly, took the PPTT's | **Fixed.** `domain_tree` takes the PPTT's L2 (a core's) and L3 (a package's or a node's) and meets them with CPUID's where both exist, as the kernel does. Host tests: the two-package machine with no cache leaf, and control C2's tree |
| R97-3 | The PPTT's last level was paired with CPUID's without comparing their level numbers: a PPTT that stops at L2 would be met with CPUID's L3, collapsing the last-level cache on a correct machine | **Fixed.** `PpttCaches::last_level` carries each processor's level number. Where CPUID reports a level, the PPTT's claim on it is used only if every processor's PPTT names the same level (level 2 for the L2; the same number for the last level); otherwise it is not used for that level, and each processor is counted in a new finding, "naming another cache level than CPUID", which fails the proof (ACPI 6.6 §5.2.31.2: when cache structures are given, every processor cache must be). Host test `a_pptt_describing_another_last_level_is_not_met` |
| R97-4 | `pptt_caches` did unbounded-in-practice work on a hostile table the parser accepts (a linear `listed_by` with allocations per chain step, linear node lookups) | **Fixed.** The nodes and caches are kept in arrays sorted once, each lookup a binary search; each node's depth and each cache's listing depth are computed once; every chain is walked once per node to check the rules and find its head. The work is the table's structures times its bounded depths and chains |
| R97-5 | `cpc_highest` returned a register's raw value, ignoring the descriptor's bit offset and width | **Fixed.** The field is taken out: `(raw >> offset) & mask(width)`; a width of 0, or a field past 64 bits or the access size, is refused as `Descriptor`. Host test with `read` giving whole registers: IA32_HWP_CAPABILITIES (bits 7:0) and CPPC_CAPABILITY_1 (bits 31:24) |
