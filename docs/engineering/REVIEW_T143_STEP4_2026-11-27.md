## What holds

- **`any_table` builds exactly the tables of `N` slots that meet the invariant, capacity aside** (handles/proofs.rs:74–110). Each generation is any value from 1 to `LAST_GENERATION`, each entry is full or empty, and each object, type and right is Kani's. An empty slot below its last generation is always listed. An empty slot at its last generation is listed or not, so it is free or retired. A full slot is never listed. The two orders of a two-entry free list are both built. The quota is any value from `live` to `MAX_HANDLES`. With `N ≤ 2` that is every combination the invariant allows. No `any_where` cuts out a state the invariant admits.
- **`check_whole` states the brief's invariant in full** (handles/proofs.rs:127–164). It checks `live ≤ limit ≤ MAX_HANDLES`. It checks each generation's range and that `live` counts the full slots. It checks that a full slot is listed 0 times, an empty slot below its last generation exactly once, and an empty slot at its last generation at most once. Every listed index must name a slot. Together these leave nothing else in the free list. The bound is asserted before the walks, so a list longer than `S + 1` fails rather than being cut short.
- **The state induction is sound as stated, apart from capacity.** `HandleTable` changes only through `new`, `reserve`, `insert`, `remove`, `take_all` and `duplicate` (handles.rs:144–314). `get` and `check_all` take `&self`, and `into_objects` consumes the table. Each mutating operation has a step harness. On every success path that harness runs `check_whole`. On every refusal it compares a full `Picture` of slots, free list, quota and count before and after (handles/proofs.rs:198–259). The invariant depends only on what the `Picture` holds. So the invariant holds after any sequence from `new` while each operation starts from at most two slots, and the post-state of an insert from two slots (three slots) is checked too. The exceptions are capacity (R143-S4-1) and properties that need history (R143-S4-3).
- **H1 is proved over the whole range a table keeps** (handles/proofs.rs:265–284). It takes every index below `MAX_HANDLES` and every generation from 1 to the last. `split` undoes `join`, and a handle is never 0. A handle's low 32 bits give `None` from `split`. The `+ 1` and the 24/40 division agree with the module documentation (handles.rs:3–8, 27–34).
- **H2 is exact.** `expected` is written from the slots, not through `get`, `split` or `nospec` (handles/proofs.rs:167–189). It gives `BadHandle` for top bits of 0, for no slot, for an empty slot or another generation. Then it gives `WrongType`, then `AccessDenied`: the order of OIDL §7.5 step 6 and ADR-0005 P1. The harness asserts equality with `get`'s answer for every handle and need (handles/proofs.rs:304–308), so both directions hold.
- **`insert`'s H6 is exact within the bound.** A refusal is `Limit` at the quota, with the object handed back and nothing changed (handles/proofs.rs:330–337). An `Ok` at the quota would break `check_whole`'s `live ≤ limit` (handles/proofs.rs:321). So, under Kani's allocator, `insert` refuses exactly at the quota.
- **`remove`, `duplicate`, the batches and `reserve` state their properties correctly as far as they go.**
  - `remove`: the entry returned equals the one `get` names. The handle is stale at once. A removal at the last generation leaves the slot off the free list. The very next insert does not revive the old handle (handles/proofs.rs:350–375).
  - `duplicate`: `Ok` only for a handle that meets the need, with rights a subset of the original's. The copy names the same object with exactly the rights asked, and counts toward the quota (handles/proofs.rs:401–416).
  - The batches: `take_all` is `Ok` only when `check_all` is. All `L` handles go. A refusal changes nothing (handles/proofs.rs:441–457).
  - `reserve(R)`: `Ok` exactly when `R ≤ limit − live`, and nothing changes either way (handles/proofs.rs:479–494).
- **M1 and M3 are exact; M2's soundness and order are proved for every input** (mapping/proofs.rs:28–150). No assumption restricts any input there. In `allow_from_every_bits` the three conditions partition the `u32`s. They are an unknown bit, no read, or write with execute for `invalid_args`; defined bits with read, execute and no write for `access_denied`; and the rest for `Ok`. So each branch's "only if", with "no other error", gives "exactly". The literal masks 1, 2 and 4 are the definition's bit positions 0, 1 and 2 (origin.kernel.oidl:253–261). `within` is checked over all four pairs. In `check_every_request` an `Ok` implies each of the following:
  - the decoded access and the needed rights;
  - whole pages, at least one, inside the object;
  - `Anywhere` only for flags 0 with address 0;
  - a fixed run page-aligned within `[USER_START, USER_END]`.

  That is D2, C7 and T22's "into the user half". `USER_START` and `USER_END` (usercopy.rs:15–18) match ADR-0004 H1's range. Each refusal is the one the module's order gives.
- **Each of the 15 controls plants a real bug, and each named harness reaches it with a check its `expect` lists.**
  - `new-quota-uncapped`: `new(any)` breaks "P11: live within the quota".
  - `join-without-the-one`: `join` then differs from `handle_of`.
  - `missing-slot-as-denied`: get at 0–2 slots, and `remove` at 0 slots through its `get`, see `AccessDenied` where `expected` says `BadHandle`.
  - `rights-loosened`: rights 1 against need 3.
  - `live-not-counted`: an insert's `live`.
  - `generation-not-bumped`: the very next insert revives the old handle.
  - `last-generation-reused`: the generation passes `LAST_GENERATION`, and H7 fails.
  - `duplicate-of-anything` and `duplicate-widens`: their two assertions.
  - `batch-refusal-as-success` (`Ok` with `check_all` refused) and `batch-partial` (`[valid, invalid]`, or `[h, h]` on one slot).
  - `reserve-past-the-quota`: at `live == limit` with `R = 1`.
  - The three mapping controls each break the assertion they name: bits 7, `held = READ` for `ReadWrite`, and `(ReadWrite, Read)`.

  Each `from` text occurs once in its file, which I counted. Every harness is named by a control (kani.rs:500–662). `kani-gate` would refuse otherwise (kani.rs:1348–1352).
- **The three doctests refuse what they claim, and the error codes are the ones rustc gives.**
  - `table.slots` is E0616.
  - A struct literal with private fields is E0451.
  - `Slot` named from outside is E0603.

  Doctests 1 and 2 are refused twice. The fields are private, and `Vec<Slot<u32>>` is a type with a private component, which rustc's type-privacy check refuses in an expression of another crate. So a correct control for 1 and 2 must make the field(s) **and** `Slot` public. The scratchpad's log names suggest that variant was run, but I did not read them. The statement about rustdoc is accurate as far as I know. Rustdoc reads the `E….` codes of a `compile_fail` block only when the compiler counts as a nightly build. On stable 1.100.0 they are ignored, unless `RUSTC_BOOTSTRAP` is set. xtask does not set it.
- **The runner changes are right and fail closed.**
  - `--lib` is needed: `framekernel`'s package also has the image's `[[bin]]`, which builds only for `x86_64-unknown-none` (framekernel/Cargo.toml:14–22).
  - Every earlier proof file is in a library.
  - A harness placed outside a library would no longer be built. It would then be reported "Kani did not report it" (kani.rs:1088), not silently skipped.
  - The `--doc` step (main.rs:6300) runs the only doctests in `framekernel/src`. A `grep` finds no other fenced block there.

## Findings

### R143-S4-1 (Medium): the reserve composition, and every memory guarantee of the table, rest on Kani's allocator never failing, and the lists' fixed capacity hides the code that provides them

- **Where:** the composition claim at handles/proofs.rs:28–29 and 471–475; "Not explored" at 34–36; `any_table`'s `Vec::with_capacity(S + 1)` at 75 and 89; `check_whole` at 127–164; `reserve_case` at 476–496. In the code: `reserve`'s reservations at handles.rs:178–179, `insert`'s at 201, and `remove`'s "Never grows" at 264–265.
- **Defect:**
  - `reserve` exists so that "count further inserts cannot fail: … memory for the slots is taken now" (handles.rs:168–169).
  - The proof's composition says the inserts then succeed because `insert` "refuses only at the quota". But that harness shows "only at the quota" only because Kani's allocator never fails. So the composition proves the quota half, which is already `reserve`'s first line, and nothing about memory. Memory is the half the kernel relies on.
  - Nothing in any harness looks at capacity. The invariant omits `free.capacity() ≥ slots.len()`, which `remove`'s push needs.
  - Even if it were added, `any_table` gives both lists capacity 3, at least as much as any post-state needs (at most 3 slots). So `insert`'s and `reserve`'s own reservation code is never what makes the capacity sufficient.
  - For 2 slots with `R = 2`, the second reserved insert can also start from 3 slots, outside `insert`'s bound. Lines 473–474 state that condition, but it then excludes part of `reserve_makes_room_at_2_for_2`'s own claim.
- **Failure scenario:**
  - (1) Replace handles.rs:178–179 with `Ok(())`. Every harness and every host test still passes: no host test can make the allocator fail. In the kernel, `channel_read` reserves (ipc.rs:759), takes the message off the queue, then inserts. "`reserve` above makes this unreachable" (ipc.rs:791–797). Under memory pressure an insert now fails mid-message: the objects are `forget`ed and the message is gone. That is the partial completion `reserve` was written to prevent.
  - (2) Delete `|| self.ensure_free_room(1).is_err()` from handles.rs:201. All harnesses pass. `remove`'s push can then allocate in `handle_close`, under the table's spinlock with interrupts off (ipc.rs:818). An allocation failure there stops the kernel.
- **Fix:**
  - Add `t.free.capacity() >= t.slots.len()` to `check_whole`.
  - Build `any_table`'s lists with the least capacity the invariant allows, `Vec::with_capacity(N)` for each, or a Kani-chosen capacity from `N` to `S + 1` through `reserve_exact`. Then `insert`'s reservation is what keeps the assertion true after it.
  - In `reserve_case`'s `Ok` branch, assert that `slots.capacity()` and `free.capacity()` are each at least `slots.len() + R.saturating_sub(free.len())`. With `try_reserve`'s documented no-allocation-within-capacity behaviour, the inserts' memory half then follows.
  - Restate lines 28–29 and 471–475 to say which half comes from where.
  - Add the two plants above as controls.

### R143-S4-2 (Medium): no success branch checks the rest of the table, or what `take_all` hands back, so "no operation ever adds a right" (P2) is not proved

- **Where:** handles/proofs.rs:320–329 (`insert`), 350–376 (`remove`), 401–416 (`duplicate`), 441–456 (`take_all`). The claims are handles.rs:71–73 ("nothing changes an entry's rights in place") and ADR-0005 P2 ("No operation ever adds a right"; P8: "a handle sent over IPC keeps at most the rights it had").
- **Defect:**
  - Each success branch checks the entry the operation names, plus `check_whole`. `check_whole` says nothing about the rights or objects of the other entries.
  - No branch compares the untouched slots with `before`. In `duplicate` that includes the original handle's own slot.
  - `take_all`'s result is checked only for its length. Its elements, and their order, are never compared with the entries the list named.
  - `channel_write` relies on that order: "`take_all` keeps the list's order" (ipc.rs:649–651). It zips the result with the handle values to record each moved handle's owner and an end's new holder.
- **Failure scenario:**
  - A `duplicate` that, after its checks, sets the original slot's rights to `u32::MAX` passes all three `duplicate` harnesses and every other harness. The same goes for an `insert` or `remove` that widens a neighbouring entry. Each is a direct P2 violation.
  - A `take_all` that pushes `(object, u32::MAX)` passes all six batch harnesses. So does one that iterates `list.iter().rev()`. The first escalates every right a handle carries through IPC. The second hands the receiver its handles in the wrong slots and mis-records their owners.
  - The host tests catch these particular plants (handles.rs:630–634 and the model test at 642–717). But they test sampled tables, not every table within the bound, which is what the Kani claim is.
- **Fix:**
  - In every success branch, assert that each slot index below `before.slot_count` that the operation does not name keeps its `(generation, entry)`. For `duplicate`, include the original's slot.
  - For `take_all`, compute `wanted[k] = expected(&t, list[k], need)` before the call, and assert `taken[k] == wanted[k]` in order.
  - Add one control that widens a neighbour's rights, and one that reverses `take_all`'s order.

### R143-S4-3 (Medium): H3, "a removed handle stays `BadHandle`, across its slot's reuse too", is checked for the next insert only, and the induction cannot carry it further

- **Where:** handles/proofs.rs:357–375 (the one-step look-ahead) and 21–29 (the induction). The claim is the brief's H3 and P1's "a stale handle never names a reused slot". ADR-0005's "Alternatives to E1" rejects wrapping generations for exactly this reason.
- **Defect:**
  - The induction proves a state invariant. A stale handle is history, and the invariant says nothing about it.
  - H3 for arbitrary sequences needs two step properties. First, no operation lowers any slot's generation (`remove` raises it by one). Second, a retired slot stays retired: empty, at its last generation, and unlisted.
  - No step harness asserts either. The look-ahead catches only a generation that returns to its old value at once.
- **Failure scenario:** in `remove`, replace `slot.generation += 1` with a 32-bit wrap: `slot.generation = if slot.generation == 0xFFFF_FFFF { 1 } else { slot.generation + 1 }`. Every Kani harness passes:
  - `check_whole` accepts generation 1;
  - the handle is stale at once;
  - H7 is untouched;
  - the next insert issues `(i, 1)`, which differs from the removed `(i, 0xFFFF_FFFF)`.

  The host tests drive a slot through only about 2^16 generations (handles.rs:520–539), so they do not see it either. A program still holding the slot's handle from generation 1 then names the new object. That is P1 broken, at the value range only Kani reaches.
- **Fix:**
  - In each step harness, compare every slot index below `before.slot_count`. Assert `after.generation ≥ before.generation`.
  - Assert that a slot that was empty, at its last generation and unlisted before is so after.
  - In `remove`, assert that the named slot's new generation is exactly the old plus one, or that the slot is retired.
  - With those, H3 follows by induction for every sequence within the bound, and the doc at lines 21–29 can say so.
  - Add the wrap above as a control.

### R143-S4-4 (Low): what the bound of two slots and two-element lists leaves out is not stated, and two claims are false past it

- **Where:** handles/proofs.rs:21–32 and 471–475; handles.rs:101–102 ("the table answers only for the ones it issued … (Kani's `handles::proofs`)"); handles.rs:175–176 and 198–199.
- **Defect:**
  - `insert` also refuses with `Limit` when the table has `MAX_HANDLES` slots and no free one (handles.rs:198–199). `reserve` also refuses when `slots.len() + fresh` passes `MAX_HANDLES` (175–176).
  - Retired slots stay in `slots`. So both refusals are reachable with `live < limit`. "Insert refuses only at the quota" and "`reserve(R)` is `Ok` exactly when the quota has room" are therefore true only below that boundary.
  - Neither guard is reached at two slots, so neither is proved or controlled.
  - Also unproved:
    - `check_all`'s distinctness beyond adjacent pairs, since lists hold at most 2 handles and P8 allows 64;
    - `reserve(0)`, which is `channel_read`'s call for every message without handles (ipc.rs:759);
    - free lists of 3 or more entries.
  - handles.rs:101–102 cites the proofs without their bound.
- **Failure scenario:** a check that compares each handle only with the next one (`rest.first() == Some(&handle)`) passes every batch harness. With it, `[a, b, a]` is accepted by `check_all`, and `take_all` then fails after removing two handles. A host test catches it (handles.rs:622). The Kani claim does not. Separately, a reader of handles.rs:101–102 takes the table as proved, without the bound.
- **Fix:**
  - Say in the module doc that H6's two "exactly" statements hold only while `slots.len() + R ≤ MAX_HANDLES`. Retirement, and so the MAX_HANDLES limit, rests on E1's lifetime argument, not on a proof.
  - Name the unreached guards, lists of three or more and `reserve(0)` as unproved.
  - Add `reserve_case::<N, 0>`, which is cheap.
  - Qualify handles.rs:101–102 with the bound.

### R143-S4-5 (Low): M2 and `duplicate`'s refusals are one-directional, so a check that refuses valid requests passes

- **Where:** mapping/proofs.rs:87–150; handles/proofs.rs:417.
- **Defect:**
  - `check_every_request` proves "`Ok` only when", and which error a refusal gives. It never proves that a request meeting D2's rules is accepted. Its only cover is for a fixed mapping (mapping/proofs.rs:132–135).
  - `duplicate`'s `Err` branch asserts only that nothing changed. The error, and the conditions it may refuse under, are not pinned.
  - `get` is proved exactly, by equality with `expected`. These two are not.
- **Failure scenario:**
  - Changing mapping.rs:195 to `0 if request.address == 0 => return Err(Error::InvalidArgs)` refuses every random placement, and `check_every_request` still verifies.
  - Adding `if new_rights == old { return Err(Error::InvalidArgs) }` to `duplicate` refuses the equal-rights duplicate that P2 and `rights::DUPLICATE` allow. All three `duplicate` harnesses pass.
  - Host tests catch the first (mapping.rs:571), and may catch the second.
- **Fix:**
  - Write `expected_check` from D2, D5 and the module's order, and assert `check(..) == expected_check(..)`, as `get_case` does.
  - In `duplicate_case`'s `Err` branch, assert that the error is `expected`'s refusal, or `InvalidArgs` with rights added, or `Limit` at the quota.

### R143-S4-6 (Low): the controls leave the map request's range and placement checks, and `get`'s type-before-rights order, unshown

- **Where:** mapping/proofs.rs:98–130 and 139–147 (one control, `map-rights-loosened`, for the whole harness); handles/proofs.rs:179–183; kani.rs:500–662.

  - No control swaps `get`'s `WrongType` and `AccessDenied` checks, which OIDL §7.5 orders.

- **Failure scenario:** a later edit to `check_every_request` weakens "a fixed run lies in the user half", say to drop `base >= USER_START`. The harness then stops seeing a fixed address in page 0, and no control fails to show it.

  - drop the alignment test at mapping.rs:97;

### R143-S4-7 (Low): the doctests guard the crate's boundary, not the module's, and their hand-run controls cannot notice a doctest that fails for another reason

- **Where:** handles.rs:71–102; main.rs:6297–6300.
- **Defect:**
  - A doctest is a separate crate. A field or `Slot` made `pub(crate)` or `pub(super)` is still refused there, so all three doctests still pass. Yet every user of `HandleTable` is inside `framekernel`, which is where the induction's premise ("only through its methods") must hold.
  - `free`, `limit` and `live` have no doctest of their own. Making them `pub` breaks nothing the doctests try, since doctest 2 still fails on `slots`.
  - Rustdoc on stable ignores the error codes, and the controls run only by hand. So a doctest that fails to compile for an unrelated reason, such as a renamed path or a library that no longer links, passes silently.
- **Failure scenario:**
  - A later change makes `slots` and `Slot` `pub(crate)` so that `ipc.rs` can walk entries, and edits rights in place there. All three doctests pass, and the Kani induction no longer covers the kernel.
  - Or `handles` is renamed. The doctests fail with E0433, and the step reports success.
- **Fix:**
  - Add a text gate, beside `kani-gate`, that refuses any visibility on `HandleTable`'s four fields and on `Slot`.
  - Or automate the controls as `kani.rs` does: plant `pub` in a scratch copy, run `cargo test --doc`, and require it to fail.
  - If the doctests stay, add one each for `free`, `limit` and `live` (E0616).
