## Findings

| # | Severity | Finding | Where | Status |
|---|---|---|---|---|
| 1 | High | **The space record can disagree with CR3.** `UserSpace::activate` is safe and public, and runs `write_cr3` with interrupts on. `write_cr3` stores the record (`leaving`, `loaded`) and then loads CR3. If the scheduler preempts the caller in between, its own switch rewrites the record, and the caller's later `mov cr3` makes the record name a space the processor no longer runs on. `UserSpace::drop` trusts the record, so it would free a PML4 the processor still runs on, and a shootdown for that space would skip the processor. Not reachable through today's callers (the scheduler, and a proof that turns interrupts off), but it breaks ADR-0011 N6's contract that no safe caller can break memory safety | `frame/src/cpu.rs` `write_cr3`; `frame/sync/src/shootdown.rs` `switch_space`; `frame/src/userspace.rs` `activate`, `Drop` | Confirmed by reading |
| 2 | Medium | **Activation outside the scheduler is undone on resume.** The scheduler reloads its own choice of space whenever a thread resumes (`framekernel/src/sched.rs`). A copy checked against one space can then run through another process's tables, and a system call that activated a space would return to ring 3 on it. No caller does this today | `frame/src/userspace.rs` `activate`; `framekernel/src/sched.rs` | Confirmed by reading |
| 3 | Medium-low | **A stalled `protect` is forgotten.** `protect` shoots down only when a round changed an entry. After a stalled shootdown (`Err(Stalled)`), a retry finds the entries already changed, sends nothing and returns `Ok`, while a processor that never answered can keep the old, writable translation. No frame is reused, because a stalled unmap leaks its frames | `frame/src/userspace.rs` `protect`; `frame/sync/src/shootdown.rs` `service` | Reviewer's reading |
| 4 | Was low; now blocks CI | **The kernel-half control does not fault on a real processor.** The probe page is mapped global, so the translation cached while reading through the complete space survives the CR3 load, and the read through the space that lacks the slot succeeds. QEMU's software CPU flushes its whole TLB on every CR3 write, so every local run passed | `frame/src/vm.rs` (the probe mapping); `framekernel/src/aspace.rs` (`read_from`) | **Confirmed by CI:** PR #13's boot on an AMD EPYC 9V45 (family 26) under KVM failed with "from a space lacking the slot, the same read faults: false: address spaces failed" |
| 5 | Low (policy) | **W^X is enforced per mapping only.** `map_shared` lets one `SharedFrame` be mapped read-write at one address and read-execute at another, even in the same space. That defeats W^X (CLAUDE.md §58) once programs can map memory objects (S3-5b) | `frame/src/userspace.rs` `map_shared` | Reviewer's reading |
| 6 | Low (liveness) | `edit()` waits without bound. A waiter with interrupts off, on the processor where the editor lock's holder was preempted, would hang that processor; this is documented. A kernel-scope shootdown that stalls panics after 1 s, which predates S3-5a | `frame/src/userspace.rs` `edit`; `frame/src/tlb.rs` | Reviewer's reading |
| 7 | Low (proofs) | The models run the real `Shootdown` and `RefCount`, but nothing interrupts `switch_space` in them, so finding 1 is in their blind spot. No control covers `holds()` reading `loaded` before `leaving`, or the initiator's Acquire load of `served`. Two controls count "Model exceeded maximum number of branches" as a catch, which a state blow-up alone can produce. `protect_lets_a_reader_write` cannot fail under the software CPU (the author's T10) | `developer-tools/xtask/src/loom.rs` and the models | Reviewer's reading |

Housekeeping the reviewer raised:
- `UserSpace::without_probe_slot()` is a public safe constructor of a space that breaks H2's premise. Make it available to the proof only.
- `RefCount::retain` has no overflow guard. This predates the task.
- ADR-0004 H2's table puts the heap and stacks at `0xFFFF_C000_0000_0000`, but the code puts them in the direct map. Either the ADR or the code should change.

## Checked and found sound

- **The shootdown protocol** as written, under x86-TSO and Rust's model:
  - one request at a time;
  - the request is published before its generation;
  - the target's Release store of `served` pairs with the initiator's Acquire;
  - the SeqCst fences are correct for a processor entering a space or coming online;
  - the PTE is cleared before the fence, and leaving a space through a CR3 load drops its translations, since PCIDs and global user pages are never used.
- **Stalls.** The turn is released, and frames are leaked rather than reused.
- **`UserSpace`'s locking.** `state` is never held across a shootdown, the lock order editor → state → MEMORY is consistent, and W^X holds for each entry in `map` and `protect`.
- **The kernel half.** All 256 slots get tables before use, nothing writes PML4 entries 256–511 afterwards, and kernel tables are never freed.
- **Liveness.** No deadlock cycle exists with today's callers. A caller that breaks the lock rule ends in a leak, or a panic for kernel scope, not a hang.
- **The Loom harness.** It requires each control's edit to appear exactly once, to compile, and to fail with its expected message.
