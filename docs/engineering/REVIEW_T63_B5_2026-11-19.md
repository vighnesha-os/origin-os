## The hand-over's five points

1. **A buffer longer than its field is still written in pieces.** **Keep it, and record ACPICA's difference beside G15.** ACPI 6.6 Table 19.7 (PDF 1008) says a buffer larger than a field unit is broken into pieces and written whole to the field, lower chunks first. The ledger names no firmware that relies on ACPICA's cut. So the rulings' second clause keeps Origin's choice: where ACPICA departs for no stated firmware reason, Origin's stands if ACPI 6.6 allows it. Note in the record what differs: the final value. Two bytes stored to a byte field leave the second byte under the pieces rule and the first under ACPICA's, after two device writes instead of one. It is also asymmetric with G15's strings, which are now cut. If evidence later shows firmware relying on the cut, rule it then.
2. **A boot table's locals and arguments give `OutsideMethod`.** **Confirm.** A local at a table level is a failure of execution, not of parsing: the decoder can step past it. Giving it `Grammar`, which since B5 fails a table whole, would contradict Q2's line. It also matches B4-13's run-time case, so boot and run-time loads treat it alike. The test `a_boot_tables_local_abandons_its_statement` pins it.
3. **Q3's identity is the signature, the IDs and the term list.** **Confirm, and correct the text** (B5-R7). A boot load hands the interpreter no header, so comparing the whole header is not possible there. A table that differs only in its revision or creator fields has the same AML, and refusing it loses nothing.
4. **The skip's work list is allocated per skip.** **Agree with the correction.** It is pushed with `mem::push`, charged to the memory limit, and released on every path (tolerate.rs 221–224, 242). One consequence to state in the contract's place: under memory pressure a skip can meet `Limit(Memory)`, which fails the table whole, as any limit does.
5. **A table that loads itself is refused at its own load as already loaded.** **Agree.** The table being loaded is in the table list and not failed, so `identical_table` matches it. A table that loads a different copy of itself still recurses under the depth limit, and the nested-load tests keep that bound exercised.

## Checked and found sound

- **The load policy's line** (Q2): `whole_table` is `Truncated`, `PackageLength`, `Reserved`, `Name`, `Grammar`, any limit, `Fatal`, and `Pending`, which never abandons. `run_frames` tries an abandon first, then B4's `failing_load`. A failure inside the skip, or a whole-table kind from a called method, fails the table.
- **Which statement is abandoned.** `abandon_target` takes the innermost `Block` above the innermost `Loading` frame and below any method's block. Errors inside a method end the method, and abandon the load-time statement that called it. An error in a method evaluation outside a load is never abandoned. `with_address`'s nested run, a resolution walk, has no block before its methods, so nothing is abandoned there.
- **The unwind.** Frames, calls, creators and depth are restored to the block's. A serialized method's implicit mutex is dropped. What `Acquire` took stays (G2). `Resolve` and `Loading` counts stay true through `truncate_frames`.
- **Scope openers and predicates.** A failing `Scope`, `Device`, `Method` or other scope opener is skipped by its package length, body and all. `stmt` is updated before each statement of a block. A `While` predicate is re-evaluated with the `While` block popped, so a failure on any pass abandons the whole `While` from its start. An `If` predicate failure skips the `If` and an `Else` right after it, inside the block's end.
- **Progress and bounds.** Every skip consumes at least one byte, so abandoning always advances. Each term is a unit of work, each report a unit, and 10,000 failing statements meet the step limit cleanly (the author's test).
- **G1's binding.** `Deferred` exactly where `in_load_time_code`, `Lazy` in methods. `Bind::Node` is generation-checked (`Stale`). `Bind::Empty` reads as uninitialized and exports as `Value::Uninitialized`. `initialize` binds first. A run-time load binds its own table, with B5-R2's caveat.
- **G2.** `release_call_holds` exists only as a planted fault. Re-acquisition counts depth, and release keeps ACPI 4.0's level rule. `release_reported` runs at the end of a boot `load` and of `evaluate_node` after `export`; an aborted evaluation releases silently. The ENFG/EXFG pair test, the order tests and the `Serialized` test are sound.
- **G4.** Prefix detection comes before the zero skip, so `0x…` works. Conversion stops at a bad character or at the digit that would overflow the width, keeping the value so far. Implicit buffer text is `0x` and two digits a byte, space-separated; `ToHexString`'s is comma-separated. `ToHexString` of an integer gives `0x0` for zero. A string to a buffer copies its NUL.
- **G11, G15 and G18.** A zero-length named buffer takes the source as converted (a string with its NUL, consistent with G4). A string goes to a field as its bytes, cut to the field. `table_key` requires four name characters (`Name` otherwise), pads with NUL, and reports `Range` for a long ID; an empty ID matches any; the test host matches the same way.
- **G5 and the EC transfer.** `AnyAcc` and `BufferAcc` are byte access, in naturally aligned units from the unit holding the first bit. G16's whole-span check is unchanged. The EC transfer is dispatched after the `Lock` rule's Global Lock and after a bank field's bank write. It is bounded within the region and to 255 bytes, merges by the update rule, and passes `time_for_host`.
- **Reports.** At most 64 per top-level evaluation, then one `Suppressed` from `end_evaluation`. The counter resets in `begin_evaluation`. Reports are written without allocation (paths into a fixed buffer). A boot load refused as already loaded is an evaluation of its own for its report. The bound is per evaluation as ruled: a walk of thousands of devices can still give thousands of reports in all, which the host may want to cap.
- **No new panic path, and the allocation discipline.** Every new index is `get`/checked; every new allocation goes through `mem.rs`. `Vec::new` in the skip allocates nothing until `mem::push`.
- **The kernel proof.** It binds after its loads, keeps the first report, and fails on any report, as Q9 ruled. The host test with a duplicate in an SSDT shows it. The structural-failure test keeps the rollback branch.
- **N-soak fixes and the B1–B4 test rewrites** keep each test's purpose: rollback paths moved to reserved opcodes, and Q7 tests to the already-loaded refusal.

Answered by the TASKS 63 session on 2026-11-19 (UTC), to the coordinating session's rulings of the same day, one commit for each finding on `claude/aml-tolerance`. `main` was merged in at `6b4c5e09` before the answers began; the hand-over's points 1 to 5 were built and recorded first (`1abef830`, `c4e0719d`, `77121794`), and G15's two stated limits, ruled the same day, at `fe40b139`. Host tests under the machine's turn lock on the tree the answers make (11:36 UTC): `origin-aml`'s 210 passed and 1 ignored, the kernel proof's 42 passed, formatting and both crates' Clippy clean. The full gates run once, on the final tip, after the reviewer reads these answers.

**B5-R1: fixed, `180bc6ad`.** `skip_term` takes the kind of the operand it steps over. A name becomes a call only in a statement or `TermArg` position (`TermArg`, `TermArgRaw`); in a `SuperName`, `Target`, `SimpleName` or data position it is stepped over as a name, as `decode_location` reads it. Tests from the probes: `a_place_naming_a_method_is_skipped_as_a_name` (`Store (UNDF, MT1)`, `Store (ObjectType (MT1), UNDF)` and `CondRefOf (MT1, UNDF)`, each followed by `AF1` and `AF2`: one `Abandoned` of the statement's own length, both names made); `a_place_naming_a_method_before_a_device_keeps_the_device` (B5-R1 (b): `\DEV` and `\DEV.C1` made); `a_place_naming_a_method_in_a_body_does_not_run_past_it` (B5-R1 (c): `MT2` of two arguments next to last in a `Device` body: no `PackageLength`, no rollback, the body's last name made). Control: `SkipCallsInPlaces`, the old rule, caught by all three, and by the soak's new sentinel audit (B5-R4).

**B5-R2: fixed, `adce2aac`.** The pass runs in `finish_load` before the `Loading` frame and the table's creator are popped, so a limit there takes `abort`'s path: the table fails whole, rolled back, and the trace reads `Load`, `Limit`, `Loaded(Err(Limit))`. The pass covers only the new table's names: the names load-time code puts in packages are listed as they are made, and a run-time load binds the list's last, those of its own table, a unit each. Tests: `a_runtime_loads_pass_binds_only_its_own` (the pass takes one entry, by a test-only count, whether 1 or 300 boot-table names are left deferred, and those bind later; the evaluation's whole step count proved no measure, moved more by how the interpreter's vectors happen to grow); `a_limit_in_a_runtime_loads_pass_fails_the_table` (the least step limit under which the table stays loaded found by search; one less fails it at the pass's charge, before any report, with the trace above). CL41 records the per-name cost.

**B5-R3: fixed, `d869001b`.** The list holds its names for the collector until they are bound or dropped, so a pass never depends on whether the collector ran. An element dropped past its package's count (a nested package's names included), the names an abandoned statement made, and a failed table's are marked never to bind when dropped; each is read, if ever, as a method's element is. A temporary package of a statement that completes keeps its names until the pass, so an unbound name in it is reported, either way. Test: `names_nothing_can_read_are_never_bound_whether_or_not_the_collector_ran` (P3's two cases, a nested dropped package, and a temporary package `Index` reads through `DerefOf`): the same reports with the collector run before the pass and without, only the temporary's name reported. Control: `BindDropped`. **Superseded** by the answer to the addendum's B5-R10 and B5-R11 (`b83fe91a`): the list is weak, a pass marks what can still be read, the marking by byte range is gone, and the temporary's name is no longer reported.

**B5-R4: fixed, `8be81730`.** The soak's audit gains the contract's §4.9 checks 1, 3 and 5, and a sentinel for B5-R1:
- each table's `Abandoned` reports at most its count, and a block that failed after abandoning failed whole, for a kind of its own;
- every mutex an evaluation's end, or a failed load in it, released other than by `Release`, reported, when the evaluation ended well and nothing was suppressed (a test-only count of such releases in the library);
- every host access within the region it names, the test host logging each access;
- the statement after the grammar's failing load-time statement made.

The grammar's failing load-time statements gain failing `If` and `While` predicates, an unterminated string with a byte above 0x7F inside a scope, a package with extra elements, one a package of names, and a place naming `\D0.M3`. `SkipCallsInPlaces` and `SilentRelease` join the soak's planted faults. `NoReport`: every host test of a tolerance, in `tolerance.rs`, `host_ops.rs`, `load.rs` and `namespace.rs`, fails with it planted, each in a run of its own (`fails_without_reports`). A duplicate across blocks is added too: `XA`'s load-time code sometimes names `\N1`, which the block made. The contract's `ToInteger` and `ToHexString` of random strings and buffers were in the grammar already, through `un`'s operators 0x96 to 0x99 on any expression, strings and buffers among them. Nothing of §4.9's list is left ungenerated.

**B5-R5: fixed, `3d301ff5`.** ADR-0013's AML row names the three reasons step B5 added: the binding failure, a tolerance, and a store in pieces (the hand-over's point 1). `package_names_that_cannot_be_bound_fail_the_proof`: no step limit can reach the pass in a whole proof, since a name costs its load more units than the pass and the proof's bound (three evaluations' steps) is checked before each table. So the test meets the time limit: a host clock still for its first `K` readings and 10 s on after them; the pass over 1,250 names charges them at once, which reads the clock, and for one `K` that reading is the first late one. The binding's reason comes first.

**B5-R6: fixed, `7621917c`.** `pins`' comment is back above `pins`.

**B5-R7: fixed, `62d0ce79`.** `Report::AlreadyLoaded` and the ledger say what is compared: the signature, the OEM IDs and the term list, not the revision, OEM revision or creator.

**B5-R8: fixed, `acf159d4`.** `Report::Released` gains `method`, the path of the method that took the mutex, empty for load-time code. `a_mutex_a_method_declared_is_held_past_its_names`: `TMP` declares `TMX` (level 5), takes it and returns; the evaluation ends reporting `Released([], [TMP_])`; in another, a later `Acquire` of a level-1 mutex fails `SyncLevel`, and the failed evaluation releases silently. Recorded in the ledger's G2 row as following G2.

**B5-R9: fixed, `fa0cf5d8`.** `fail_load` releases with `release_reported`. `a_failed_runtime_load_reports_what_it_releases`: a run-time table takes `\MX` and then meets a reserved opcode; `Load` gives Zero, the evaluation goes on, and one `Released([MX__], [])` is told. Control: `SilentRelease`, for both release tests.
