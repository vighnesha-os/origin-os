## Checked and found sound

**The clean step (`817cd16`, `74c1e49`)**

- The first form named no package. Cargo's page says `--release` removes "artifacts only in the release directory" [doc]; the author measured that it then ignores `--target` and removes the host's `release` directory [author]. It deleted build outputs, not sources [inferred]. The run then stopped, since the stale file is read again after the second build [code].
- The second form always names a package. `clean_arguments` refuses an empty list, and it is the only place the arguments are made [code]. `linked_packages` cannot be empty for the kernel; for the userspace it is a constant with one entry [code].
- `built_into` takes only `<dir>/<target>/release/<file>` for the kernel's or the userspace's target [code]. Only those two kinds of file are ever passed in: the kernel's ELF and the carried programs [code]. The loader is a PE file and never passes through here [code].
- The clean runs in the repository's root with the cargo that runs `xtask` [code]. A package that matches nothing, or any other failure, is an error that stops the build [code, inferred for Cargo's part].
- For the userspace's target every carried program is cleaned, which is more than the one stale file. The build that follows names every carried program, so each is built again [code].
- A stale file cannot pass: each relinked path is read again, and one that still lacks the fixed line is an error after one more build, never a third [code, and the test holds it].
- The test holds the kernel's exact arguments, the userspace's shape and the refusal [code]. It cannot hold what Cargo does with them; only the stale-directory runs show that [author].
- In history, `817cd16` to before `74c1e49` keeps the wrong form. A bisect that lands there with a stale image loses `<target dir>/release` and stops. Build outputs only.
