## Checked and found sound

By reading, unless marked:

- **H1.**
  - `usable_namespace` refuses protection information (DPS.PIT, any non-zero type), then metadata in the format in use (MS of that LBAF), whether extended or in a separate buffer, since the check does not depend on FLBAS bit 4.
  - The format index: FIDXL, plus FIDXU only when NLBAF + 1 + NULBAF exceeds 16, which matches NVM CS 1.3 (FLBAS, p. 86; §5.6, pp. 160–161). An index at or past that total, or past 63, is refused before the table is read, and the read is bounds-checked.
  - LBADS outside 9 to 16 is refused, and so is NSZE × block size past 64 bits, so later products cannot overflow.
  - A block larger than a page refuses that namespace, by name.
  - The refusal comes before any I/O command: `choose_namespace` runs before I/O queue 1 is created.
- **Transfer sizes.**
  - The block layer moves 4096 / block size blocks into one 4 KiB page, and `Block::new` requires the block size to divide the page.
  - `read_blocks` caps each command at one page.
  - The proofs that move 8 blocks run only on the 512-byte test disk.
  - So no transfer exceeds 4 KiB. MPSMIN must be 0, and the smallest non-zero MDTS is then 8 KiB (Base 2.4 byte 77, p. 368).
- **DMA ownership.**
  - DMA frames are never freed (`DmaFrame`; `DeviceDma::page`), so dropping `Nvme` on a failed bind frees nothing the device can reach. `init` clears bus mastering on every failure after bind (I12).
  - A fault that may be live (`NoCompletion`, `WrongCommand`, `QueueDied`) kills the queue and keeps the page out of use: `Transfer::Stuck` for the block layer, the gate killed in `cpu_command` and `io_thread`.
  - A dead queue is never polled again, so a late completion is never taken.
  - `command()` with the driver taken out returns `QueueDied` and leaves the gate claimed, so nothing reuses the queue or its page.
  - `io_thread`'s kill is skipped when the driver is out, but its gate stays `Busy`, which has the same effect.
- **Deadlines.**
  - `submit_on` takes the deadline from `deadline_ms(qid == 0, opcode)`, so admin 00h is not taken for Flush. `run`, `command`, `cpu_command` and `io_thread` each use the deadline it returns.
  - `command`'s wait for its turn is at most 30 s.
  - Every loop is bounded by a deadline or by the 1,024-entry list.
  - `await_csts` prints at most one line a minute, and none for a wait of 60 s or less.
- **Ruling (a).**
  - "Not proven" is set only from `pairs < 2`, which depends on the allocated queues and BAR 0's doorbells (the processor count always asks for at least 3), or from an MSI-X table with fewer than 2 entries. Any other failure stays a failure.
  - `prove_iommu` expects 0 NVMe routes only in that case, and `d.msix` is then `None`.
  - xtask demands the proven interrupt-driven, per-CPU and x2APIC lines on every gate configuration, so a regression cannot pass there as "not proven".
- **Ruling (b).** MSI Enable (bit 0) and Multiple Message Enable (bits 6:4) of MSI's Message Control are cleared before MSI-X Enable is set (PCIe Transport 1.4 Figure 36, p. 23; §3.5.2, p. 15). The read-only low half of the dword is written back unchanged. Every MSI-X entry is masked before the function is enabled.
- **Ruling (c).**
  - CNS 07h goes with CDW11 0 (CSI 0) and NSID 0. NSID 0 lists from NSID 1, in increasing order, and CNS 07h lists only the set CSI names (§5.2.14.2.2 and §5.2.14.2.7, pp. 413 and 416).
  - The walk stops at 0h, and stops with an error at FFFFFFFEh, FFFFFFFFh, an NSID past NN, or one not above the one before.
- **Ruling (d).**
  - CAP.CRMS is bits 60:59. CRTO is at 68h, with CRWMT in bits 15:0 in 500 ms units (Figure 57, p. 99).
  - CAP.TO's text sends a host with CRIME 0 to CRWMT for the rise (p. 83).
  - CRTO is read only when CRMS is not 0. The rise waits the larger of CRWMT and TO, and the fall waits TO. The arithmetic stays below 2^45.
- **Ruling (e).** Matches byte 111 (p. 375).
- **Ruling (f).** Matches the ruling. A namespace refused for a status, or for a format, is named with its NSID; an admin timeout still fails the bind.
- **The other fixes.**
  - M2: MQES applies to the I/O queues on PCIe (p. 84), and admin queues of 32 lie within AQA's 2 to 4,096 (p. 92). With at least 2 entries, `entries - 1` cannot underflow.
  - M5 and L1 as the contract says.
  - L3: `next_cid` never gives FFFFh.
  - L5: `Status::is` compares the type and the code.
  - L10: the admin queue's SQID is 0, which `answers` expects.
  - IOCSS is CAP bit 43 (CSS bits 44:37, p. 82).
  - INTMS is left alone while MSI-X is on (p. 85).
- **Untrusted values.**
  - `Capabilities::decode` bounds every field.
  - The doorbell arithmetic and `doorbell_queues` cannot overflow, and the stride is never 0.
  - `allocated_queues` returns at most 65,536 each.
  - Queue ids and vectors stay within `u16`.
  - Each transfer's block count is at least 1, so `blocks - 1` cannot underflow.
  - Completions are masked field by field, and SQHD is used only when it is below the queue's entries.
  - The Identify parsers index with `get`, and the text fields keep printable bytes only.
  - Nothing a device returns reaches an unchecked subtraction, an index or a division.
- **Controls.** By their recorded lines, none of NV-1 to NV-16 failed for a reason other than its aim. The xtask failures in NV-11 to NV-13 come from the markers' fixed namespace 1 and the fixed MSI-X line, as the rows say. `645f3ce` keeps the first failure in `POLLED`, which matches NV-16.

Not verified: the host tests and controls pass as recorded, and the gate runs (the reviewer ran nothing).
