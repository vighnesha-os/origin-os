## How they were taken

Each value is a number from a line the kernel prints on every boot, read from the job's log. The lines are in `framekernel/src/sched.rs` (context switch), `wait.rs`, `ipc_proof.rs`, `ipc_proof/events_ports.rs`, `time.rs`, `kernel.rs` (lookups, the random request, timers), `aspace.rs`, `stacks.rs`, `storage.rs`, `console.rs`, `pcie.rs`, `virtionet.rs`, `ipc_proof/memory_objects.rs`, `ipc_proof/directory.rs`, and `framekernel/frame/src/smp.rs`. The script that read the logs is not in the tree. A `cargo xtask` command that does this at each run belongs to the task that builds ADR-0018 V8's gate.

What a guest's figures cannot show:

- A virtual processor that halts is woken through the host. The paths that wake a processor (the two ping-pongs, the ports' round trip, the unmap under a running thread) carry that, and their spread is wide.
- "Ticks" are TSC ticks. Under QEMU's software processor a tick is about a nanosecond and instructions cost differently from silicon (ADR-0012).
- The NVMe, PCIe, UART, framebuffer and network figures are QEMU's device models, not devices. In a guest each access to one leaves the guest, which is why a UART section can keep interrupts off for milliseconds there.
- The virtio-net ping's unit is microseconds; a boot with no reply printed 0.
