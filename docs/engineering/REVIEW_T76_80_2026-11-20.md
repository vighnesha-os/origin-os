## Findings

### T76-80-1: Medium. TASKS 80's boot control is not in the change and no result is recorded

- **Where:** `framekernel/src/ipc_proof.rs` (whole change); `docs/engineering/TASKS.md`, item 80.
- **What is wrong:** TASKS 80's done criterion ends "with a boot control that refuses a start and looks for the line." Neither commit contains such a control. The message of `a77402a6` names no planted control and no result. By contrast, `649ea562` does state its planted controls.
- **Evidence:** `git show --stat a77402a6` touches only `ipc_proof.rs`. Its message names no control. My brief says a script is editing `ipc_proof.rs` in the working tree at this moment, which may be that control running.
- **Suggested fix:** Before the item is called done, record the control:
  - which step was made to refuse, and how (for example, `start_thread` forced to `Err(Full)` for one program);
  - the line seen in the serial log;
  - that `boot` was refused on `: ipc failed` at that line, not at the end on a missing marker.

  Put this in the commit message or the hand-over. Running the plant once through `start_program` and once through the inline RFLAGS.AC path would show both code paths print. This finding is open. It is not a defect in the code.

### T76-80-2: Low. Host tests cannot catch a regression in the target wiring of `ExceptionReport`'s Debug

- **Where:** `framekernel/frame/src/trap.rs:71-75`, `:92-96`, and the tests at `:166-172`, `:189-224` and `:228-245`.
- **What is wrong:**
  - The test that refuses a raw `rip`, `debug_tells_rip_as_an_image_offset_and_prints_no_address`, calls `fields` directly through `AsKernel`. `AsKernel` uses a teller the test wrote itself: `Shown(tell(addr, &bases))`, a copy of `phys::told`'s body.
  - The real `Debug::fmt` is exercised only on the host, where `told` is `Told::Address`, the identity.
  - The one line that does the work on the kernel is the target `told` → `crate::phys::told`. It is compiled only for `target_os = "none"`, and no test reaches it.
  - ADR-0013 C47 covers the console's report line, which does not use this Debug.
- **Failure scenario:** Suppose a later edit makes the target `told` return `Shown(Told::Address(addr))`, or makes `Debug::fmt` call `self.fields(f, |a| Shown(Told::Address(a)))` on the target. All three host tests still pass, and the kernel's Debug prints `rip: 0xffffffff8…` again.
- **Suggested fix:** Either of these:
  - (a) Add a boot-side check in the style of C47: format `{:?}` of a synthetic `ExceptionReport` whose `rip` is a function's address in the image, require `rip: image +0x`, and fail the boot otherwise. A plant that makes the target `told` the identity is its negative control.
  - (b) State the limit in the test's doc comment and in the hand-over: what the host test shows is that `fields` tells `rip` through its teller, not that the kernel passes `phys::told`.

  Option (a) closes the gap. Option (b) only records it.

### T76-80-3: Low. `QueueError`'s derived Debug is still printed in the boot log, so "which nothing prints" is not true of the tree

- **Where:** `framekernel/src/sched.rs:1120` and `:1139-1145`, which predate this change. `framekernel/src/runqueue.rs:356-364` (`#[derive(Debug)]`) and `:474`. The claim is in `a77402a6`'s message and in its doc comment at `framekernel/src/ipc_proof.rs:1992-1993`.
- **What is wrong:**
  - The new `Display for NotRun` deliberately avoids `QueueError`'s Debug, because `BadContext(u64)` carries the first frame's address in the stack region. `sched.rs:1120` sets `frame_at` (built in `spawn_with_fpu`), and `runqueue.rs:474` returns it.
  - However, the scheduler proof prints `reused: Result<usize, QueueError>` with `{:?}`: "… exited threads freed their slots (slot {:?} reused)…".
  - If that spawn were refused with `BadContext`, the boot log would print `Err(BadContext(<decimal address in the stack region>))`. ADR-0004 A6.3 forbids printing an address in the stack region during boot as well as after it.
- **Failure scenario:** A defect that makes `build_first_frame` return a misaligned frame, or any other path to `BadContext`, makes the scheduler proof print a stack-region address before it fails. This is latent: it needs a separate defect to reach it. It is outside this change's diff, but it is exactly the leak path this change was written to avoid.
- **Suggested fix:** Give `QueueError` a hand-written `Debug` that prints `BadContext(..)`, as `Hooks`, `Bases` and `GuardedStack` already do. That closes the leak for every printer, and `NotRun` could then use `{:?}` instead of listing the variants. `runqueue.rs` is also compiled inside `origin-sync` for Loom (`sync/src/lib.rs:53`), so the impl must use `core` only. The cost is that the host `assert_eq!` messages in `runqueue.rs` (for example `:1524-1525`) lose the value on failure, which is acceptable. Alternatively, rewrite `sched.rs:1141` to print only the slot or the error's name. Either way, correct "nothing prints" in the record, or route it to the coordinator as a follow-up item.

### T76-80-4: Low. A scratch-memory failure is printed as a script failure

- **Where:** `framekernel/src/ipc_proof.rs:1984-1985`, `:1998` and `:2069-2070`.
- **What is wrong:** `NotRun::Script`'s doc comment says "Its scratch memory or its script", and line 2069 maps both `image.scratch()` and `image.script(..)` failures to it. The printed text, however, is "its script could not be written". `scratch()` (`:444-448`) writes `MSG`, `SIZES` and `BAD_SIZES` into the data pages, not the script.
- **Failure scenario:** A failed `write` of `TEXT` into the data page prints "the pinned code range program was not run: its script could not be written: ipc failed". That points the reader at `SCRIPT_PAGES` and `write_script`, which were never reached.
- **Suggested fix:** Print "its scratch memory or its script could not be written". Or split the step into `Scratch` and `Script` with separate `if`s, which costs one more variant and gives an exact line.

## Checked and found sound

**`abi_and_entry` (TASKS 80)**

- **Early returns:** the old function had 22: seven programs × (image, `finish`, `start_thread`), plus the pinned program's scratch/script check. All 22 now print exactly one line, through `not_run`, before `false` reaches the caller:
  - Six programs (registers, pinned code range, null GS, no developer calls, sidt, single-step) go through `start_program`, which prints on each of its three refusals and returns `None`. The caller then returns `false` without printing a second line.
  - The pinned program's image and scratch/script refusals print inline (`:2066`, `:2070`).
  - RFLAGS.AC prints inline on all three refusals (`:2113`, `:2116`, `:2120`).
  - No other early return exists in the function (`:2043-2211`).
- **Behaviour on success is unchanged:**
  - Same order: image → (scratch, script) → `finish` → `start_thread`.
  - Same arguments: `bsp`, `CODE`, `STACK + PAGE`. The `rdi` values are unchanged: `SCRIPT` for the pinned program, 0 for every other.
  - Same `Limits`, including `debug_calls: false` for the no-developer-calls program.
  - Same success lines, byte for byte. Same `ok` accounting.
- **RFLAGS.AC ordering:** `cpu::ac_leaks()` is still read after `finish` and before `start_thread` (`:2115-2119`), as ruling Q3b requires.
- **Lifetimes:** the thread `ObjectRef` that `start_thread` returns on success is dropped right after the call, as before. `.is_err()` dropped it at the end of the condition. `if let Err(..)` drops it at the end of the `if let` under edition 2024's rescoping, with nothing in between. On refusal, the process `ObjectRef` is dropped inside `start_program` instead of at the caller's `return`. Nothing runs between the two points.
- **The new line prints no address:** the program names are literals. `NotRun`'s `Display` writes static strings only, and names `BadContext` without its value. The match over `QueueError` is exhaustive, so a new variant fails the build rather than printing something unchecked.
- **The boot checker:**
  - Every new line ends `: ipc failed`, which is in `boot_failures` (`main.rs:2630`) and matched by substring.
  - No line starts with a `REFUSE_COUNT_LINES` prefix, so `lost_stacks_only` returns `None` and ADR-0013 Amendment 3 cannot forgive it.
  - `kvm_forgives` does not cover `ipc failed`.
  - The new line is therefore a failure line on every accelerator.
- **Lints, by reading:**
  - `NotRun` is private, so `missing_debug_implementations` does not apply. Every variant is constructed, and `Thread`'s field is read by the match.
  - `const` items after statements trip only `clippy::items_after_statements`, which is pedantic.
  - The intra-doc links are private to private.
  - The `bool` that `not_run` returns is not `must_use`.
  - The new names collide with nothing: `launch::start_program` is always called by path.

**`ExceptionReport` and `Hooks` (TASKS 76)**

- **Fields:**
  - `vector` is a `u8`.
  - `error_code` is the processor's error code, or the 0 the stubs push (`cpu.rs:2496-2509`, `has_error_code`). Every gate except the system call's is DPL 0 (`descriptors.rs:78-79`), so ring 3 cannot raise an error-code vector with `int n` and misalign the frame. The claim that `error_code` is never an address therefore holds.
  - `rsp`, `rax` to `rdx`, `rflags`, `cs` and `machine_check` are left out (`finish_non_exhaustive`).
- **The host test** `debug_tells_rip_as_an_image_offset_and_prints_no_address` asserts the exact string. Every field that can hold an address is set to an address in a sliding window, and the machine check's text names the image base. A `rip` printed raw inside `fields` fails it.
- **`Hooks`' Debug** prints `Hooks { .. }`. Its test asserts the exact string and the absence of `0x`. It covers every distinct function, since `reschedule`, `yield_now` and `exit` share `frame_hook`, and `block` shares `timed_hook`.
- **`phys::told` is safe from an exception handler and from `Debug`:**
  - It loads atomics only: `DIRECT`, `KERNEL_VIRTUAL`, and `STACK_REGION_BASE` / `STACK_REGION_DRAWN` through `stack::region`. It takes no lock, does not allocate, and cannot panic.
  - `tell` and `Offset::between` subtract only after comparing, so the kernel's release overflow checks cannot fire.
  - Before `phys::init`, the image base reads 0 and an image address would print as `image +0x<the address>`. That cannot reach the report hook, which is installed at `kernel.rs:101`, after `phys::init` (`early.rs:151`). Nothing in the tree calls this Debug.
- **The `cfg` split:**
  - The target `told` exists only where `crate::phys` does.
  - The `Told` import is cfg'd to the host, where alone it is used, and `Shown` is used on both sides. There is no unused import or dead code on either target.
  - The only other host build of `origin-frame` is `tests/emulator/reserved-memory`'s dev-dependency. No userspace (`linux-gnu` triple) crate depends on `origin-frame`.
- **Conventions:** this matches TASKS 70's style. `Probe`'s Debug uses the same `&format_args!("{}", crate::phys::told(..))`, and `GuardedStack`'s uses `finish_non_exhaustive` with address fields left out.
- **Commit-message claims checked:** "All 22 early returns", "Six programs go through `start_program`", "found by TASKS item 79's control C1w" (matches the TASKS 80 text), "rsp, rax, rbx, rcx and rdx … stay out, as before" (the old Debug printed only `vector`, `error_code` and `rip`), and "the derived Hooks Debug put back fails one". All are accurate. For "raw rip … fails two tests", see T76-80-6.
- **Formatting:** both committed files pass `rustfmt --check` under edition 2024.
