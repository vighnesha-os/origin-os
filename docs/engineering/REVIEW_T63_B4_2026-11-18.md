## The author's eleven points

1. **A `Fatal` inside a run-time load fails that load with Zero, and the evaluation goes on.** **Disagree.** It follows Q3's words, but `Fatal` is the firmware asking the OS to log and shut down (§19.6.47, PDF 1050). The same `Fatal` ends a method's evaluation with `Err(Fatal)` and is swallowed inside a loaded table (R5: `LD` returned 77 and wrote `AFT` after it). End the evaluation, as a limit does (B4-2).
2. **`Return` in a loaded table is `Grammar`; `Break` and `Continue` stop at its block.** **Agree.** `return_crosses_load` finds the nearest `Call` or `Loading` frame; `leave_loop` pops only `If`, `Else` and `While` frames, so it meets the table's block and answers `NotInLoop`. A test covers `Return`; none covers `Break` in a loaded table, which the code makes plain.
3. **A table a block's own load-time code loaded and completed stays when the block fails (Q8).** **Defensible, and needs an explicit ruling.** It matches Q8's reason (stores stay; AML has no transactions) and treats a top-level load and a run-time one alike (R4 shows the run-time case behaves the same). But Q8 was asked about an evaluation, and this extends it to a load, which the host's `load` documents as rolled back whole. With point 4 it can leave a partial table. My recommendation: keep it, rule it in the coordinating session's words, record it in the ledger, and test both cases (B4-3).
4. **An inner table's names under an object of a failing outer table go with that object; untested.** **Confirmed by running (R4), and sound in memory:** the subtree goes, the inner table stays not failed, an alias it made answers `Stale` even after a new object of that name appears, and its method answers `NotFound`. The same happens on the ordinary path, when the parent is a method's temporary (R4b). Needs tests and a record (B4-3).
5. **`LoadTable`'s order: key lengths, root path, `DSDT`/`SSDT`, host.** **Agree.** §19.6.78 makes an over-long string a run-time error; a `DSDT` key with a bad root path being an error is a fair consequence. The root path's object kind is not checked (B4-4).
6. **The parameter store runs after the load is complete; its error ends the evaluation unless an outer load catches it; the table stays.** **Agree with the semantics** (§19.6.78: a missing object is a run-time error after the table is added). **But** the store can need a PCI function first, and then the load's end runs twice (B4-1, R8).
7. **G18.** **Agree,** as a strict choice. Note what it means for an empty `OEMIDString` or `OEMTableIDString`: only a blank field matches. The rule is stated for hosts in `host.rs`, and the load tests exercise NUL against space padding.
8. **A host calling `out` twice.** **Agree it is the safe direction** (an uncredited charge). **Disagree with the claim** that `host.rs` says it calls once (B4-11).
9. **The frame size.** **Agree.** `Loading` is `Copy`, keeps what the end needs (two operands, marks, root, cursor), and the GC marks its operands.
10. **`bfbc229a`.** **Agree.** `applied_limit` returns the real limit outside `cfg(test)`; production is unchanged, and the control no longer depends on which check refuses first.
11. **The planted faults.** **Agree they are wired** to tests that would fail: `LoadUnchecked` (both checks, by `a_bad_checksum_gives_zero` and `a_block_not_signed_ssdt_gives_zero`), `KeepFailedLoad`, `InvertLoadResult`, `AllowDuplicate`, each with a clean run. I read the table; I did not run `planted_faults_are_caught_by_the_load_tests` or `random.rs`' control. None plants B4-1's path.

- **Every byte run is checked first.** `Load` runs only the span `check_signature` accepted, from the interpreter's own copy; `LoadTable` requires a length equal to the copy, a checksum, and the key's signature and IDs, before `begin_load`. No AML runs from host memory.
- **Rollback of a failed load** (outside B4-1's path): frames, calls, creators, holds (implicit ones included), depth and cursor return to the `Loading` frame's marks; the table's names go with its creator; its bytes are released; `abort` fails each table still loading and traces each, after the limit.
- **Limits across a nested load:** one evaluation's steps, time and loop counts; one level of call depth per load; one memory budget. The memory sweep test refuses each allocation of a nested load in turn.
- **No Rust recursion:** `begin_load`, `finish_load` and `fail_load` run as frame steps or inside `run_frames`' loop; chained failures are a `while` loop.
- **The region read:** within the declared span, naturally aligned, a unit of work each, the memory charged before the first access, and refused at boot by `BootHost`.
- **Memory:** every copy (buffer, region, field, host copy, the table's AML) is charged and released on each path; the `tables` vector's room is reserved before the copy.
- **`DataTableRegion` (B2-14):** the copy is checked before its address is taken; five failing cases give `Host(Failed)` with nothing read.
- **Q11:** only symbols `origin-acpi-tables`' own object defines, and only after that crate passed its own check in the same run; both conditions are in the comment and the code. `LAYERS` and the `unsafe` gate cover the new edge.

## Resolution

Answered by the TASKS 63 session on 2026-11-18, on the coordinating session's rulings of the same day. Each fix is a commit of its own on `claude/aml-load`, after `ac0bbc3b`; the review was copied in at `585a7c1d`. **B4-1 (Medium): fixed, `a427ef35`.** Every store a load makes is made ready before anything changes, as `Divide` does.
