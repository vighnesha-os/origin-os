## Findings

| # | Severity | Finding | Where | Status |
|---|---|---|---|---|
| A | Medium | **A stall is taken to mean "the change is made" when it may not be.** The kernel turns every `ChangeError::Stalled` into `timed_out` and then acts as D5 says: the change is made. The framework also returns `Stalled` in two cases where it is not: (a) the flush that must come first after an earlier stall (`confirm`) stalls again, and nothing has changed; (b) a middle round stalls on a range over 128 pages (`CHUNK`), and the later rounds never run. `memory_unmap` then removes the mapping's record and drops its object while pages are still mapped. `memory_protect` records the reduced access while pages may still be writable, and a retry returns OK with no shootdown, because the record already says what was asked. Threat row M14 is untrue in those cases. Reached only if a processor fails to answer a shootdown within a second, which no program can cause on purpose | `framekernel/frame/src/userspace.rs` `unmap`, `protect`, `confirm`; `framekernel/src/memory_object.rs` `unmap`, `protect` | Confirmed by reading. **Sent to the framework's author:** after `Err(Stalled)` every page of the range must have its final entry, frames whose flush was not confirmed stay leaked, and the space stays marked unconfirmed. If that proves unsound, a distinct "nothing changed" error needs a status of its own, which is the owner's decision (§84) |
| B | Low to medium | **A failed map causes a shootdown nobody pays for.** `map_pages` maps page by page. When a page fails, it unmaps the pages before it with the result discarded and no price. A process that has used its 32 page-table frames can ask for a fixed two-page mapping that crosses into a region with no table: one page maps, the next fails, and each call costs a shootdown outside the budget that M8, T15 and T16 rest on. If that cleanup itself fails, pages stay mapped after the record is gone | `framekernel/src/memory_object.rs` `map_pages`; the framework has no call that maps a range wholly or not at all | Confirmed by reading. **Sent to the framework's author:** one call that maps a run of shared frames, all pages or none, with no entry ever present on a failure and so no shootdown. The kernel's author adopts it afterwards |

Low observations, sent to the author to fix or to record as intended:
- A change to a mapping that another thread is changing returns `invalid_args`. D5 does not name the case.
- Eight colliding random draws return `limit`. D5 does not name the case.
- A map that races with another into the same space, between `reserve`'s check and the mapping, returns `invalid_args`. The call asked for under B removes the separate check.
- Control 17 (map ignores the handle's read and write rights) is caught by the corpus only, not by the proof's own lines.
- `Budget::new` gives a rate above 10⁹ units a second an interval of zero, so every unit is free. Not reachable today: only the kernel's own proofs set limits. It needs a bound before a creator's call can set a rate (step 4).

## Checked and found sound

- **What a request may ask** (`mapping::check`), in D5's order: the access bits, the handle's rights for them, the range inside the object with checked arithmetic, then the placement. Write with execute, or no read, is `invalid_args`; execute is `access_denied`; a fixed address must be page-aligned and wholly inside the user half.
- **Locks.** No lock of these modules is held across an address-space operation. A record is reserved busy before its pages are mapped and is busy again while it changes; each lock is taken briefly with interrupts off.
- **The charge.** An object is charged to its creator's account before its frames are taken, and the charge goes back when the object is dropped, on every failure path too. A mapping holds its object, so closing the handle does not escape the quota.
- **The budget.** Unmap and protect are priced before they run and refused with `should_wait` with the record put back and nothing changed; what the change cost beyond its price is charged afterwards. The arithmetic is checked or saturating.
- **Protect only reduces.** A request that adds anything is `access_denied`; one that changes nothing returns with no shootdown and no price.
- **Placement.** The mapping limit is checked before entropy is drawn (D5's order). A place comes from the processor's random-number instructions only, and their absence is `not_supported`.
- **Unsafe code.** Both modules forbid it, and the gate counts none outside the framework.
- **The proof's line that failed on PR #13** (`directory`, below) is not S3-5b's.

## Also found: a race in the directory proof (S3-2, PR #13)

PR #13's CI failed at `490c4d0` in one boot under QEMU's software CPU (the AMD-IOMMU bridge machine, 2 processors): `directory: the scripts ran as written: client Some(Exited(0)) false`. Both real-processor jobs and `cargo xtask check` passed.

The kernel is right and the proof's script is not. The client passes one end of its `missing` connection to the directory and then writes on its own end, expecting OK. The directory closes the end it received without waiting. If the directory runs between the client's two calls, the write returns `peer_closed` (`framekernel/src/ipc_proof/directory.rs`, `client_script`).

**Sent to the proof's author:** write on the connection's own end before passing its other end, on a branch from `490c4d0`, with a control that makes the directory run first. PR #13 stays a draft until its CI passes.

## Resolution

S3-5b is landed on the step-3 batch's local branch (`land/s3-part2`, `09c84a9`). Nothing in findings A–D lets one process reach another's memory or escape its committed quota; A needs a processor that has stopped answering, and B and D are bounded by the table and mapping limits. They are fixed before the batch that carries S3-5b is offered for review:

1. The framework's author fixes A, B and C in `framekernel/frame/`.
2. The kernel's author fixes D and the low observations, then adopts the framework's new call and brings rows M8 and M14 and the tests into line.
3. The coordinating session reviews and lands each, and updates this record with the commits.
