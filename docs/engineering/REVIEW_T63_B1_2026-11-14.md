## Checked and found sound

By reading, unless marked:

- **No Rust recursion.** The engine is one loop over a heap frame stack; deep copies, export, import, the collector and namespace removal use work lists. The one self-call, `read_node` on an `Alias`, unaliases first and refuses an alias result, so it goes one level deep. `Drop`, `Clone` and `PartialEq` on `Object` and `Val` are shallow; the recursive `Value` type is limited to 64 levels on export and import.
- **No panic site found** outside the lint-checked forms: indexing, arithmetic, `unwrap` and casts are all checked; the one panicking slice method, `copy_from_slice` in `decode_string`, gets equal lengths by construction. Every loop advances or is bounded: the field-list loop (each entry moves the cursor), `descriptors`, `set_bits`, `get_bits`, `ToBCD`, `unalias`, `settle` and `peek` (16 hops), sibling and parent walks (acyclic by the leaves-first removal).
- **Package length** (§20.2.4): one to four bytes, bits 4–5 refused when bytes follow, the length counting itself, checked against the innermost enclosing block or package (`after > end` and `end > enclosing` refused); a term that runs past its block is refused at the next step.
- **Name strings** (§20.2.2): root and parent prefixes, dual and multi (count 1–255) and the null name; every segment validated; `^` above the root gives `NotFound`, never a wrap. Search rules apply to single relative segments only; creation never searches.
- **Operand kinds** against Table 20.2: every opcode matches, `CondRefOf`'s and `Load`'s second operand taken as `Target` (E3, E4); 0x5B 0x83 accepted per the ruling; reserved values, 0x5B 0x2A among them, refused with table and offset; `LNotEqual`, `LLessEqual` and `LGreaterEqual` decoded as pairs, which equal `LNot` of the inner comparison.
- **Method invocation**: arity from the method's flags when the name is decoded; a name in a place is never called (E6); `_OSI` as a built-in of one argument; package elements keep names unresolved.
- **Field lists**: reserved, access, extended access and connection entries; the list must end exactly at its length; a connection buffer is bounded by the field's end; flags bit 7 refused.
- **Buffers and packages**: `Buffer`'s size is the larger of size and initializer (§19.6.10); huge sizes and counts are refused by the charge before anything is allocated; more elements than the count refused; missing elements uninitialized.
- **Integer width**: masked at every entry (constants, `Ones`, stores, results, imports, buffer-to-integer); 32 bits for a revision-1 DSDT.
- **Conversions** checked against Table 19.7: string to buffer with the NUL and the empty string to an empty buffer; string to integer as hexadecimal, no `0x`, empty refused; empty buffer to integer refused; buffer to string as spaced hexadecimal; integer to string as 8 or 16 digits.
- **Stores** against Tables 19.8 to 19.10: a local is overwritten; an argument holding a reference is stored through; a named object converts to its type; a field keeps its type and `CopyObject` to one takes an integer or buffer only; a named buffer keeps its length (G11).
- **References and lifetimes**: object and node handles carry generations; local and argument references carry the activation's serial, never reused; every dereference re-checks type and bounds.
- **The collector's roots** are complete: every live node's object, every operand of every operand frame (values and reference places, the package under construction and its carrier frames included), every call's locals and arguments, and the result. It runs only at the start of a step and at the end of an evaluation; no handle is held in Rust across a step; the mark stack is reserved one entry per slot, so marking never allocates.
- **Rollback and dynamic names**: every node a table or a call creates goes on its creator's list, reserved before the node exists; a failed load or a limit removes every creator's nodes; a returning method removes its own. The tests and the randomized snapshot check exercise both.
- **The limits** are checked where the contract says: steps at each step, loops at each repeat, depth at each call, time at loop, call and every 1,024 steps, memory at every charge. On a hit, frames, calls and creators are dropped and the garbage collected (F1 and F2 are the exceptions found).
- **`handle_error`** is unreachable in today's code: every growth in `mem.rs` follows a `try_reserve_exact` that left room. Nothing proves it stays so (F3, F5).
- **`host.rs`** says the host, not the library, enforces ADR-0019 A2, that regions are only what the firmware names and never memory the kernel or a program owns, and that `Fatal` is a report.
- **`_OSI` and `_REV`** follow ADR-0019 Amendment 1: one `const` table of 22 Windows strings answering Ones, everything else Zero, `_REV` 2. The strings were not compared with Microsoft's page.
- **The encoder** uses no code of the crate; its package-length encoder is written separately from the decoder.

## Resolution

Written by the author, the TASKS 63 session, on `claude/aml-interpreter`. Nothing above this section is changed but the "Status" column. The coordinating session ruled on each finding and on the records; each ruling is named where it applies. Every answer is a commit of its own, after B2's commits (`9985c06`, `4fda5b3`, `1c7e757`) and apart from them; no commit up to `56a21dc` was rewritten. No person has reviewed the answers, and the reviewer has not yet read them.

**F1 (High): fixed, `ac2c74a`.** A step is now an opcode or a unit of the work between opcodes, counted where the work is done: each name compared in a sibling search (`Namespace::child`), each field-list entry and each field unit made, each element `Match` reads, each element exported, the collector's slots by eight, and one for every 64 bytes charged to the memory limit (so copies, conversions and fills count by what they allocate). The clock is read every 1,024 units, not every 1,024 opcodes. A namespace removal goes down the subtree and back by parent links in time linear in its size, and unlinks a node in constant time (`prev` links). Test (`limits.rs`): a `Field` of 300,000 names and a `Scope (\MISS)` after it ends with `Limit(Steps)` under the service limits on the wall clock (0.95 s, release build) and with `Limit(Time)` at 2.002 s under a 2 s limit and no step limit, rolled back both times; deterministic with a step limit of 1,000,000. The randomized test's adversarial blocks show the same for nesting 5,000 deep and 4,096 names in one scope (`Limit(Steps)`, and with room for the work, `Limit(Memory)` and `Duplicate`).

**F2 (Medium): fixed, `67f5bef`.** Each path the finding lists releases what it charged: a heap slot or a table entry is reserved before its payload is made, a partial package copy gives back its elements, a failed `ToDecimalString` its text. Each top-level evaluation and load then ends with `recount`, which counts every byte the interpreter holds and sets the budget to it, so a charge missed on a path not yet found is given back at the end. Test: 30 runs that copy a package into the memory limit leave `memory_used` where it began; the semantic corpus and that test assert that the count never under-stated what was held. Control, run once: without the releases and the recount, the test fails.

**F3 (Medium): fixed, `497d7b1`.** `probe.rs` instantiates the interpreter with a host that refuses everything (and, since F9, traces), and `no_panic_probe` calls `new`, `load`, `lookup`, `evaluate_node`, `path_of`, `initialize` and `connect_space`. The no-panic check builds the release object for `x86_64-unknown-none` as before and now requires the probe's symbol and the engine's `run_frames` in it, so a change that drops them fails rather than passes having seen nothing. Building that object showed two panic sites the lints did not: `Vec::remove`'s index assertion and the sort's `panic_on_ord_violation`; both replaced (`retain`; a linear walk in `region_scopes`). Control, run once: a `panic!` planted in `exec.rs` puts `core::panicking::panic_fmt` in the object, and the check refuses it.

**F4 (Medium): fixed, `283bfb3`.** The generator now writes blocks that load and run: load-time predicates of names and constants (one in ten any expression, so that a load still fails after making names), locals set from values that read nothing, packages whose count covers their elements, true binary operators only, small integers half the time, `Break` and `Continue` inside loops but one time in ten, and `Sleep` up to 1.5 s. The tests assert floors at 500 cases or more: grammar blocks 90% loaded, 15% of evaluations returning a value, 20% completing 32 operations or more, 14 kinds of error with `Limit(Time)`, `Limit(Memory)`, `Limit(Depth)` and `Region(Refused)` among them; mutated blocks 8%, 12%, 18% and 15 kinds with `Grammar`, `PackageLength`, `Truncated` and `Reserved`. The default seeds give 98%, 21%, 31% and 20 kinds, and 12%, 20%, 27% and 21 kinds; seed `0x63300000` gives 98%, 23%, 32% and 19 kinds, and 12%, 18%, 28% and 22 kinds. A third of the cases are timed: one second, the clock moving 5 ms a read. Each of the 20 adversarial blocks has the outcome it was written for, asserted in both integer widths, under a plain, timed or roomy setup. Seven planted faults are `cfg(test)` knobs in the library (`tests::Fault`): a failed load's rollback skipped, a method's names kept, no loop limit, no time limit, the memory limit checked at twice its value (weakened, not removed, so that no run asks the machine for more), a buffer field a byte past its buffer, the Global Lock kept. The control test runs 300 grammar, 300 mutated and the adversarial cases unplanted, then with each fault, and requires a failure whose message names the check that caught it. The statistics of the soak on the answers' last commit are in the provenance entry. Writing the floors found G14 (F11).

**F5 (Low): fixed, `8b922dd`.** The allocation gate refuses each growing method wherever it is named (`.push(`, `Vec::push`, a method path), each growing type's constructors (`Box`, `Rc`, `Arc`, `VecDeque`, `BTreeMap`, `BTreeSet`, `BinaryHeap`, `LinkedList`, `FromIterator`), `Vec::from`, `String::from`, `.into(` and the allocating macros, outside `mem.rs`. Host tests name each form, and the planted control in every `check` run is kept. The library's own `.into()` conversions became `Error::from`.

**F6 (Low): fixed, `4ba74e0`.** Under `cfg(test)` the engine notes each opcode, name prefix, local, argument, constant and string it completes; `run_corpus` keeps what ran in the cases that passed their checks; the coverage test requires every entry of Table 20.2 to have been both emitted and run so. Control, run once: with `Mid`'s checks removed from the corpus, the test fails naming 0x9E.

**F7 (Low): fixed, `6a08c3f`.** A failed table keeps its identity (its methods answer `TableFailed`, a name kept pointing into it `Truncated`) and gives its bytes back. Test: twenty more failed loads of a table of about 16 KB raise `memory_used` by less than 256 bytes each.

**F8 (Low): fixed, `ba5c190` and `786e9c7`.** Node generations are 64 bits; object handles keep 32, since every holder of one is traced by the collector. The wider generation made the operand frame larger than the block frame, and Clippy's `large_enum_variant` refused the enum from `ba5c190` until `786e9c7`, which keeps it unboxed (boxing would allocate outside `mem.rs`) and says so.
