## Checked and found sound

- **Where the check sits [code].** `syscall::run` judges the origin first, with interrupts still off, before the dispatcher and before any copy from user memory. Nothing is read from ring-3 memory, indexed or looked up by a ring-3 value before it: the path from the entry is the saved frame, `sched::current_user`, one read of the process's `origin` field and the comparisons.
- **The arithmetic [code].** Both subtractions are wrapping. A return address below 2, or below the base, gives an offset no stub has. No checked arithmetic touches a ring-3 value on this path, so the kernel's overflow checks cannot be reached from it.
- **What RIP is [code; the processor's part inferred].** Every IDT gate is made with DPL 0, and the one DPL 3 constructor has no caller. So `syscall` is the only way in from ring 3 besides a fault, and the frame's RIP is RCX as `SYSCALL` left it: the address after the instruction. The address compared is that less two, the place of the bytes `0F 05`, whatever prefix stood before them.
- **The number is judged whole [code].** `frame.rax` goes as a `u64` to `pinned` and to `dispatch`. Both `match` on the whole value. A stub's `mov eax, imm32` clears the upper half, so bits above 31 can reach the kernel only by a jump to a `syscall`, and then no arm matches and the thread stops.
- **What a refused caller learns [code].** A pinned process gets no status: its thread ends. Step 4 has one thread a program and no call that makes a thread, so it cannot try again. The base is no secret from the program itself: its import slots hold it. No call returns another process's base, and no boot line prints a base. A proof process gets `access_denied`, for a range it was given.
- **A jump to a stub's own `syscall` with that stub's own number is accepted [code].** That is the stub's call with its extensions and its R10 move skipped. The decoder judges the whole register, so it earns `invalid_args` where the stub would have extended. This is threat row C7 and it is right.
- **Jumps into the middle of a stub [code, inferred].** A jump into the bytes of a stub's earlier instructions makes the processor read other instructions and then reach the stub's `syscall`. One worked example: `handle_duplicate`'s stub entered one byte in reads as a divide through RAX and then `syscall`. None of this matters to the pin. The image holds the bytes `0F 05` at the 20 pins and nowhere else, at any alignment (the build's rule, reviewed at R1), so every such path ends at a pin, and there the kernel accepts only that pin's own number. What ran before the `syscall` is not something the kernel relies on (row C7).
- **`refused` [code].** It is the exit path's own sequence in the same context: interrupts on, `thread_ended`, the two reaps, interrupts off, `ThreadExit`. `run` does exactly that around `thread_exit`. The clone of the thread's context that `run` holds is dropped on return in both; the scheduler keeps its own until the thread is reaped, so the space outlives the processor's stay in it.
- **The kind is fixed [code].** `origin` is a plain field. Its one writer is `map_core(&mut self)`, which runs only while it is `Core { base: None }` and records the base only after the mapping succeeded. A proof process and an already mapped one are refused. Once the process is behind an `ObjectRef` with a second holder, no `&mut` exists.
- **Who makes a pinned process [code].** `launch::load_program` alone. No system call makes a process or a thread. A pinned process cannot make or change a process of the other kind.
- **`memory_unmap` and `memory_protect` cannot name the image [code].** Both take the target's record of exactly that base and length (`Mappings::begin`). The image has no record: `map_into` goes to the address space directly. So both answer `invalid_args` before the space is asked, for the caller's own process and for any process it holds a handle to.
- **A fixed `memory_map` over it is refused [code].** The space refuses a run with any page already mapped, from its own records, which hold every present user page (`prepare_run`). The kernel turns that into `invalid_args`. A fixed address in the programs' region is otherwise allowed, and the hostile memory script maps one there through the stubs, so the refusal is the image's.
- **Nothing a program maps is executable [code].** `mapping::check` allows read and read-write only; execute is `access_denied`. A memory object's frames are its own fresh frames, so no object can hold the image's frames, and no second view of them can be made by a call.
- **W^X across spaces [code].** Every mapping of the image is `Access::ReadExecute`, counted in each frame's `Aliases`. A writable mapping of a counted frame is refused, and a change from execute to write in one step is refused. The framework would let a mapping be made read-only or removed; the kernel's memory calls never reach it for these pages (above).
- **The image's place [code].** A random page of `[0x1000_0000, 0x1000_0000_0000)`, from the kernel's generator; with none, nothing is launched. It is mapped first. The program's whole span and the stack with both its neighbours are each checked free before they are mapped, so they cannot overlap it. Start records and random `memory_map` placements use `[0x1000_0000_0000, 0x7000_0000_0000)`, which is apart.
- **The frames' life [code].** The module's static holds one reference for ever. Each mapping holds one more and gives its executable count back when its space is dropped. A launch refused part-way drops the child, and with it the mapping. A space that a processor still has loaded when it is dropped is leaked with its counts; then the proof's "mapped by no process" clause fails, which is the safe side.
- **If the install failed [code].** `map_into` finds no frames and answers out of memory; `load_program` returns `no_memory` and drops the child. No boot takes this path.
- **The binding [code].** `program::check` runs before anything is made. An import slot must be 8-byte aligned, ascending, inside the file bytes of a read-only-after-relocation segment, no relocation slot, and name an export that exists; the program's fingerprint must be the carried image's. `fill_page` writes the export's address there and adds the base to relocation slots; the two sets cannot overlap. Each page is mapped once with its final access and written through the frame `map_page` returned for it. A slot's page is never writable to the program at any time. A program with no imports is launched and can make no call.
- **The launch path cannot panic on a description [code].** Every index is `get`, every sum is bounded by `check`'s limits (a span of at most 2 GiB below 2^44), and the no-panic lints apply.
- **The install [code].** One frame a page, written a word at a time from `image_word`, every word read back before the frames are kept, the rest of the page `int3`. It runs after the random-number proof and before `sched::prove`, where every proof that makes a process runs. A second call is refused. No `SharedFrame` leaves the module: it gives a mapping, a physical address, two counts and a yes or no.
- **H1 [code].** Every thread starts from one constant, `0x202`, through one path (`spawn_user`). The pin program's entry is its own: `pushfq`, `pop`, a store, a jump to `_start`; none changes a flag or RDI. The proof judges the eight bits on two processors. `_start` no longer clears the direction flag. The kernel returns from a call with IRETQ and the flags `SYSCALL` saved, so a program's direction flag is its own from entry on. The common trap entry clears DF and AC for the kernel.
- **What each proof clause would catch [code].** With the check out, the own-code call returns and reports, so the clause fails. With a range over the image in its place, the two jumps are accepted and fail theirs. A writable image does not fault on the write. A removed or re-protected image fails `core_mapped`, which also compares each page's frame with the kernel's own, so a copy fails it. An unbound slot fails the binding. A proof process stopped by the pin would end `Refused`, not by its own `ud2`. These agree with what CP-1, CP-4, CP-7 and CP-8 record.
- **`unsafe` [code].** The kernel crate's root forbids it, and `syscall.rs`, `process.rs`, `core_image.rs`, `launch.rs`, `program.rs` and `ipc_proof.rs` say so again. In ring 3 two files gained it, both of the pin program, both on the gate's list with a true reason, and the program's root denies it elsewhere. `calls.rs`: one `unsafe extern` block and one call macro, with its reason. `raw.rs`: three naked functions, a `static mut` written once by the entry, four raw reads and writes that claim nothing and say so, and `ud2`. No block declares `preserves_flags`. `runtime/rt/src/entry.rs` lost an instruction and gained no `unsafe`.
- **No new dependency [code].** `Cargo.lock` gains the pin program, the client crate's new name and `onbf-pack` as a test dependency of xtask. All are first-party.

Inferred and not verified: that every processor in scope leaves the next instruction's address in RCX for a prefixed `SYSCALL` as for a plain one; that `-C jump-tables=no` stops data tables in general (this build has none in the pin); that the framework's shootdown and count bookkeeping is right (S3-5's proofs, not reread beyond the functions named).

- **K1, `aef9f47`; control CP-11.** (3) `Process::write_frame`, the kernel's own way into a process's pages, refuses any frame of `origin.core`, by its physical address (`core_image::is_core_frame`): every process that maps the image maps those frames, so this covers a write through any process, not only through its own `origin.core`.
