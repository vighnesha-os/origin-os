## Checked and found sound

By reading, unless marked:

- **Secrets.** `KeyFile` keeps its bytes in a private field, wipes them on drop, prints as `KeyFile(..)`, and is built with exactly its 104 bytes of capacity, so it never reallocates. `HostKey`'s `Drop` still wipes the Ed25519 seed, and `mldsa87::SigningKey` has its own `Drop`. `new_key`, `new_test_key` and `from_test_seed` wipe both seeds on every path, error included. `load_key` wipes what it read on success and on failure. No secret is printed or put in an error; `xtask` writes no key file and prints key IDs only. The coverage is the same best effort `onbf-sign` records (moves leave old bytes).
- **Randomness fails closed on every path.** `fill` zeroes the buffer, then refuses an error or an all-zero result. Key generation stops at the first failure and makes nothing; signing returns before ML-DSA runs and wipes `rnd`. Test keys are deterministic by design and take ML-DSA's hedge through the same `fill`. Both `OsRandom`s read `/dev/urandom` with `read_exact`. The host test covers a failing and an empty `Random` for key generation and for signing, and that the failing one is asked once.
- **The key-file checks moved intact.** Same `O_NOFOLLOW` values, metadata from the opened handle, regular file, no group or other bits, one read; new files `create_new` with 0600 and 0644, all or none; the output-is-the-key check. Every case of the four old file-level tests is in `command_line_keys` (symbolic link, directory, 0644, 0640, missing, damaged, each position of keygen over an existing file, the same path twice, the modes written, the committed test keys), and the byte-level refusals stay in the library's test with two more lengths. Error text and exit statuses are unchanged by reading, but for a failing generator, whose message now begins "no randomness:".
- **`HostKey::from_test_seed`** marks its key as a test key and `xtask` says "with a TEST KEY"; it adds no capability the old `--insecure-test-seed` path did not have.
- **`carried::update`** cannot return a name that writes or removes outside the output directory: every name is checked to be one non-empty path component that is not `.` or `..`, and `stale`, unchanged, removes only `<name>.<k>.bin` names read from the directory itself, so S4-1's F9 holds. The callers write through a rename and remove with `remove_file`, which act on a link, not its target.
- **Same bytes.** `pack_kernel_to` passes what the old command line defaulted to (no CPU features, empty flags) and the toolchain from the same `rustc -vV` text: the old program inherited `cargo()`'s working directory, the repository's root, as `ask_rustc` runs there now. The signing time parses to the same number. `oidl` is given the same relative file names and the versions file's text, `generate_output` returns exactly the old command line's file set (its test compares them), and `mirror` writes the same `rust/` and `core/` subtrees. The author's `reproducible-compare` shows 40 files the same (its evidence file read, not run).
- **The interface gate is as strict as before:** the same trees compared, and a lock with a changed fingerprint is refused, as is one that re-recording would change (a new minor unrecorded).
- **Build profile.** `onbf-sign`, `origin-crypto` and `onbf-merkle` are optimised in the dev profile; overflow checks and debug assertions are now on for the libraries inside `xtask`, which can only fail closed. No `cfg(debug_assertions)` path exists in the three crates. The timings are recorded.
- **The libraries today.** By search, their non-test sources use `std::collections`, `std::rc`, `std::fmt::Write` and `std::error::Error` only; no `io`, `path`, `thread`, print macro, or `env!` outside string literals that become generated code; `include_str!` of the two templates only. So the rule holds now, whatever the gate's gaps.
- **G1 and G2 on the forms they claim.** A literal or `const` beginning `run`/`r` anywhere inside `.arg(…)`/`.args(…)` (`vec!`, `split` and raw strings included); a package or `[[bin]]` name, alone or as a path's last component, inside `Command::new(…)`; `current_exe` attributed to the innermost function, a stale allowance refused; written-out `std::` paths and use groups, globs, `::std::`, `/dev/` literals and the five print macros. On `e6fd12c` the gate named exactly the six `cargo run` sites and the old host access (evidence file read).
- **`oidl`'s command line** only parses, reads, writes and prints; each decision is a library call.
- **`target/xtask/test-keys/`** is named nowhere in the tree but dated corrections and the README's history (search).
- **`HostKey` is no longer `Send` or `Sync`** (`RefCell<Box<dyn Random>>`); no caller shares one across threads.

## Resolution

Written by the author, the TASKS 60 session, on 2026-11-14, under the coordinating session's rulings of the same day. No person has read the answers.

- **F1, fixed, `01ac811`.** A `#[cfg(test)]` item now ends at a depth-0 `;` or `,`, with the block it opens, or before a bracket that takes the depth below where it started, excluding nothing past it. Host test: a test-only field, last field, variant, last variant, match arm, arm with a block and parameter, each followed by a function using `std::fs`, which is caught (the test fails on the old scan); a per-run control plants such a field in `onbf-sign`'s real `lib.rs`.
- **F2, fixed, `936d155`.** G1 reads every file in a `.cargo` directory of the tree on each run, takes each alias (`[alias]` and `alias.<name>` keys, strings or arrays, followed alias to alias) whose expansion runs a program, and treats it as `run`: refused in an `.arg`/`.args` list unless it is an option's value (`--package xtask`) or `xtask` re-running itself from a function `SELF_RUNS` lists.
