## Checked and found sound

By reading, against the brief's eight questions.

- **Read-only, for real (1).**
  - **The host refuses everything that reaches hardware.** `BootHost` refuses `read`, `write`, `transfer`, `bridge_bus` and `table`, grants the Global Lock as a count without touching the FACS, and returns at once from `sleep_ms`, `stall_us`, `notify`, `fatal` and `debug`. `breakpoint`, `tracing` and `trace` take the trait's defaults.
  - **The host is the library's only exit**, and `Region` and `Host` errors come only from the host's answers. No `HostError` value is made in the library.
  - **The requests the brief names:**
    - `Load` and `LoadTable` answer `NotSupported`.
    - `_REG` (`connect_space`) is never called.
    - `DataTableRegion` gets nothing, because `table` refuses.
    - The Global Lock is balanced by the interpreter (`end_evaluation`, `release_held`), and the proof requires grants equal to releases.
  - **The tables.** `lend_if` copies each header and lends only the XSDT, the first FADT, and the DSDT, SSDTs and PSDTs, never a structure that changes after boot. It lends through `firmware::bytes`, which refuses the kernel's RAM, maps read-only, and refuses the `CHANGES_AFTER_BOOT` signatures. Every definition block passes `Checked::parse` (length, checksum) before it is loaded, and the interpreter copies the AML into its own heap.
  - **The lends repeat the census's**, so on QEMU they take no new lending slot.
  - **`Recorder` overrides every `Host` method**, and an answer that is not `Refused` counts as answered.
  - **The rest of A2, A3 and T1 to T6.** The interpreter reaches no memory through the kernel but its heap and the lent tables (T2), and the ring-0 run is B3-2's question.
- **Verdict (2).**
  - **What `allowed` accepts.** Its `Region` rule matches host refusals in spaces 0 to 2 only. Transfers come back as `Region` errors with space 4 or more, and are not accepted.
  - **The required refusals** are well defined on the boot matrix's q35 machines, each of which declares an HPET, CPU devices with `ACPI0007`, and `LNKx` links. They are QEMU's, which is B3-2.
  - **The walk is not cut silently.** Its bound comes back as an error, and the proof fails. An evaluation cut by what the walk has left is reported as that device's failure. Nodes without `_STA` or `_INI` are visited without a check of the bound, but that visit is linear and bounded by the node count, and the walk is complete.
  - **The outcome list's failure is caught** (`kept`).
- **Heap (3).**
  - **The window is exact.** `before` is read at 499, after which:
    - the interpreter lives and dies inside `interpret`;
    - `outcomes` is dropped at 1062;
    - the named results' `Value`s and arguments are dropped each pass;
    - `path_of`'s vector is dropped in its arm;
    - the console allocates nothing on write.
  - **No other code allocates in the window.** The APs spin on `GO` until `sched::prove`, and interrupt handlers do not allocate (`memory.rs`'s safety comment).
  - **A failed allocation is clean.**
    - `KernelAllocator::alloc` returns null when the heap finds no frames or no slab slot.
    - Every growth in `origin-aml` goes through `mem.rs`'s `try_reserve_exact`.
    - The proof's own allocations reserve first.
    - `Budget::refused` restores the peak and the work count.
    - Values cross the API at most 64 levels deep, so their drops are shallow.
- **Stack (4).**
  - **The proof itself does not recurse.**
  - **The interpreter's Rust depth is fixed by its code**: B2-1's fix makes a PCI lookup `Pending` or `AddressCycle`, `with_address` runs one nested frame run, and the index-field chain recurses through `unit_read` to `field_at` up to the chain's limit.
  - **The 32 KiB release proxy** is a meaningful smoke test, with the caveats of B3-7.
- **Time (5).** The walk is bounded (B2-7 fixed). The rest is B3-1.
- **`unsafe` and boundaries (6).**
  - **No `unsafe`.** `aml_proof.rs` has none, and `framekernel/src/lib.rs`'s `forbid(unsafe_code)` covers it. It covers `encode.rs` too, when the kernel's tests include it.
  - **The new dependency keeps the layering.** `origin-aml` is a leaf with no dependencies in `LAYERS`, like `origin-acpi-tables`, and no third-party crate is added (CLAUDE.md §5).
  - **Moving `origin-aml` to `FREESTANDING_LIBS` widens its checks.** Its clippy runs now include `x86_64-unknown-uefi`, and the no-panic loop's filter keeps its own allowance exactly as before. The gate gap is B3-3.
- **xtask (7).**
  - **Matching.** Markers are matched in order (`serial::contains_in_order`), and failure words in complete lines only.
  - **The failure word.** `; aml failed` is printed only by `Verdict`, and is a substring of no other line in the tree.
  - **Firmware text cannot forge a line.** The strings a table controls pass through `Ascii`, at most 4, 6 or 8 bytes between separators, so a table cannot print the failure word or the passing markers.
  - **The verdict marker's count** comes from `Proof::ALL.len()`.
- **Records (8).**
  - **The row and the code agree on the class.** The `bootproof.rs` row is Report, as ADR-0013's row says, and the row's list of failures matches the code.
  - **The count tests are consistent**: 63 + 6, 2 + 67, 66 and 68 of 69.
  - **Each control exercises what it says.** AML-1 fails on the checksum refusal of the corrupted copy, AML-2 on the named result, AML-3 on the HPET's reason first (B3-5), and AML-4 on the heap.

## Answers to the hand-over's questions

1. **The heap check.**
   - **It is exact.** "Before" is read before anything the proof allocates, and "after" once the interpreter, the outcome list, the arguments and every returned `Value` are gone. Nothing allocated outside the window is freed inside it, and nothing inside is kept.
   - **Its preconditions are unstated** (B3-4): no other processor or handler allocates in the window, and the console allocates nothing. Both hold today, and both would need checking if the proof moved after `sched::prove`.
2. **A third source of `Host(Refused)`.** There are four sources in the library:
   - `bridge_bus`;
   - `table`;
   - `acquire_global_lock`'s error;
   - `release_global_lock`'s error.

   With `BootHost` the two lock sources cannot be `Refused`, and `table`'s are failed by `seen.tables != 0`. With any other inner host, `lock_other != 0` fails the lock's. No third source passes the rule today, but the rule is global and rests on those checks (B3-9).
3. **Can a data `_HID` reach the host?** Yes, in four ways:
   - a `_HID` that is a `FieldUnit` is read through the host;
   - one in a PCI_Config region also runs the device's `_ADR`, `_SEG` and `_BBN` methods (`with_address`);
   - a package `_HID` whose elements name fields reads them at export;
   - an `Alias` `_HID` has type code 0, passes the `METHOD` test, and runs the method it names.

   Every access is refused, so nothing is touched, but each costs up to a full evaluation outside the walk's bound (B3-1).
4. **The markers.**
   - **They are right for the matrix.** They are ordered, robust against a missing line, and backed by the failure word.
   - **The HPET requirement** is right for these machines. A future machine without an HPET would need its own marker, `(no HPET)`, and that alone, since `w.hpet == None` passes the proof.
5. **`encode.rs` by path.** Acceptable for tests, with the precedent you cite.
   - **The `unsafe` gate does not scan it** (it is under neither `framekernel/` nor a listed leaf), but it compiles under the kernel's `forbid(unsafe_code)`.
   - **A change to it now runs both crates' tests**, and `check` runs both.
   - Worth a line in `origin-aml`'s provenance row, which owns it (A19-A5).
6. **`virt` for rows A19-A3 and A19-Am1.** Yes, once CI's KVM jobs show the proof's passing line. The 32 MiB evidence comes from the discovery machine, which CI holds out, so that figure stays `emu`.

### Answers to the updated hand-over's questions

1. **`Bound`'s time.** At boot it uses the same monotonic clock as everything else, which is right. On the host the clock is 0, so only the steps decide there, and the time arm is untested (B3-14).
2. **The dedupe scan.** It runs only for an SSDT or PSDT entry, after that entry's bound check.
   - **One pass costs** at most one compare per earlier entry: about 2 million for a 16 MiB XSDT, a few milliseconds.
   - **The whole scan costs** at most the bound plus one pass, so no bounded list is needed.
   - **A cheaper option, if wanted:** the lending record already caps distinct lent tables at 128, so a fixed array of the SSDT and PSDT addresses loaded so far would make each pass constant.
3. **`steps_done`.** Right.
   - **It is summed once per top-level evaluation:** every load, `evaluate`, and each walk evaluation calls `end_evaluation` once.
   - **It leaves out** the walk's node visits and the load's AML copy, which the time arm covers.
   - **It is unaffected by tracing**, since N-soak-2.
4. **`plain`.** Read-only, as checked above.
5. **The order change.** Right. Note it in AML-3's record when the controls are rerun (B3-16).
