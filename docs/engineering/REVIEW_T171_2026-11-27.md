## Areas where nothing was found

- **Writes (its question 1):** the guard is at the top of `submit_on`, the only function that writes a submission entry, reached from `run`, `submit`, `command` and `cpu_command`. The admin queue, queue 2 and every queue on a disk without the mark have no span; queue 1's span is set before `prove_io`'s first write, and each processor's queue copies it before the queue is created on the controller. SLBA and NLB are decoded right and `checked_add` keeps the check from overflowing; a Flush to FFFFFFFFh is refused; the admin list covers every admin command the driver builds.
- **The decision (2):** right in every GPT state the contract lists; more than 16 used entries makes a copy invalid; the span cannot cover LBA 0, either header or either entry array.
- **The guard's move (3):** for an allowed command nothing changes: the command identifier, the `Busy` retry, the deadlines and the counters; a refused command returns at once and is counted once.
- **Privacy (4):** the serial number is printed nowhere; on a disk without the mark no line prints the disk GUID, a unique GUID or a partition name.
- **The per-CPU encoding (5):** the stored-plus-one values and `finished` are right, and an unfinished thread reads as `WRITE_FAILED`; the block cache's early return is right.
- **The markers (6):** every new format string matches its marker character for character, in the new order; the image is read after QEMU is stopped and waited for.
